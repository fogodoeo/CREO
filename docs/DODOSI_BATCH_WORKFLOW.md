# 도도시 예약 묶음 (2026-11-24)

- 운영 관리 → 배송 → 도도시 배송 입력. 기존 배송 관리의 토큰·카드·44px 조작 영역을 유지한다.
- 접수 결과 확인 → 미접수 10명 선택 → 묶음 입력 → 도도시 결제 → 접수 결과 확인.
- 최대 10명은 받는 사람 수다. 합배송 개체는 한 사람 안에 유지한다. 자동 선택은 낙찰 결제 완료 건만, 결제 미확인은 개별 선택만 허용한다.
- 기존 `prepared` 이력은 예약 완료 증거가 아니며 새 묶음을 나누는 기준으로 사용하지 않는다.
- 입력 완료와 배송예약 완료는 별개다. 도도시 전체 목록과 상세의 접수번호·상태·출발지·도착지·수령인·전화·마릿수·맡김일·도착일을 대조한다. 결제 대기, 중복, 불일치, 읽기 실패는 완료로 처리하지 않는다.
- 동일 이름의 정거샵 확인창은 지역 포함 전체 이름이 유일하게 일치할 때만 자동 선택한다.
- 묶음/대조 결과는 회차 설정에 revision 잠금으로 저장한다. 새로고침 후 이어서 입력할 수 있다. 실제 결제·배송 상태나 문자 발송은 변경하지 않는다.
- 일부만 예약된 묶음은 예약/결제대기 건을 제외한 미접수 전원만 새 묶음으로 이어간다. 기존 탭은 수신인과 수량을 읽어 확인하며 무조건 덮어쓰지 않는다.

검증: 1440/390/320px 로컬 렌더, 10명 제한, 미결제 직접 추가, 재시작/중복/동시 revision, 합배송, 동명이점 확인창, 완료/결제대기/취소/불일치 회귀 테스트.

외부 검증 한계: 로그인한 실제 계정은 예약 목록 0건이다. 저장한 실제 HTML에서 전체 목록 구조는 확인했다. 비어 있지 않은 실제 예약 상세 스키마는 첫 실접수 이후 추가 검증해야 하며, 지원하지 않는 상세 형식은 자동 완료하지 않고 대조 오류를 표시한다. 결제와 약관 동의는 자동화하지 않는다.
