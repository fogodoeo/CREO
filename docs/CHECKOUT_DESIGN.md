# 옹동2 거래 페이지 디자인

대상: 구매자 수령·결제, 업체 판매 관리, 주관사 배송비 정산.

## 공통 기준

- 흰색 표면, 옅은 회색 배경, 진한 본문·금액. 옹동2 코랄은 로고에 남긴다.
- 주요 행동은 파란색, 대기는 중립색, 확인 완료는 초록색, 오류·취소는 빨간색으로 구분한다.
- 화면마다 지금 해야 할 행동을 먼저 보여준다. 내역·설정은 필요한 순간 펼친다.
- 구매자는 수령지 선택 후 결제 방법을 본다. 업체는 처리할 구매자를 먼저, 정산과 설정을 아래에서 본다.
- 금액 위계와 입력·버튼 크기는 세 페이지에서 통일한다. 모바일 본문 입력은 16px 이상, 터치 영역은 44px 이상을 기본으로 한다.
- 설명 문장은 상태와 다음 행동을 이해하는 데 필요할 때만 쓴다. 장식용 배지·강조색·애니메이션을 추가하지 않는다.
- 이름·금액·주소가 길어도 가로 스크롤 없이 읽을 수 있어야 한다. 키보드 포커스는 보이게 유지한다.
- 공통 표현은 `public/checkout-pages.css`, 결제 상태 표기는 `public/checkout-client.js`에서 관리한다.

## 확인 순서

로컬 실제 페이지와 가상 데이터로 확인 → 사용자 피드백 반영 → 사용자 확인 후 운영 반영.
미리보기에서 실제 주문·입금·알림 발송을 실행하지 않는다.

## 2026-09-12 1차 스타일 검토

범위: 위 세 페이지의 스타일, 문구, 업체 페이지의 읽기 순서. 결제 정책과 서버 저장·발송 로직은 이번 디자인 수정에서 변경하지 않았다. 위험도는 중간으로 분류해 인접 흐름 회귀 검증을 수행했다.

| 발견 사항 | 반영 |
| --- | --- |
| 페이지별 주요 버튼과 대기 상태의 색 의미가 다름 | 공통 파란색 행동, 중립색 대기, 초록색 완료 |
| 업체 설정·정산이 구매자 처리보다 먼저 보임 | 실제 DOM 순서를 구매자 → 정산 → 설정으로 조정 |
| 주관사 팝업 금액이 일반 입력 크기로 덮임 | 금액 선택자의 우선순위를 수정 |
| 정산 내역이 없는 상태의 글자가 흐림 | 공통 보조 본문 색 적용 |

검증: 관련 Node 테스트 37개 통과. 로컬 Chrome에서 320·390·520·1024px, 긴 정보, 초기·대기·완료·빈 상태, 팝업 및 CSS 200% 확대를 포함한 45개 화면 조합에서 검사한 가로 넘침·입력 글자 크기·컨트롤 이름·텍스트 대비 문제와 JavaScript 오류가 발견되지 않았다. 키보드 포커스, 팝업 바깥 클릭·Escape, 잔액 미리 채움과 일부 입금 잔액, 업체 필터, 외부 결제 안내, 수령지 선택 전 결제 숨김을 확인했다. 구문·UTF-8·diff 검사를 통과했다.

판정: 로컬 사용자 검토 가능. 가상 데이터 기반이며 실기기 Safari, 실제 결제·문자·알림톡 발송, 운영 배포 검증은 포함하지 않는다. 운영 사이트에는 아직 반영하지 않았다.

## 2차 거래 흐름 반영 — 로컬 검토 대기

- 결제 방법 변경은 개인 구매자 링크에서 직접 저장한다. 결제 신고·일부 확인·완료·발송된 업체 내역은 변경을 차단한다. 기존 승인 대기 건의 검토 기능은 호환을 위해 유지한다.
- 구매자 저장 버전을 확인해 오래된 화면의 덮어쓰기를 거절한다. 같은 저장 요청의 재시도는 중복 반영하지 않는다. 변경과 업체 안내 대기열은 함께 저장한다.
- 기존 카드 안내가 있으면 구매자 화면에서 내리고 업체의 처리 필요 목록에 취소할 건을 표시한다. 업체가 외부 결제 앱에서 취소·차단 후 확인한다. 사이트가 외부 결제를 자동 취소하는 기능은 아니다.
- 새 구매자 등록에서는 인증된 개인 링크의 전화번호에 해당하는 이전 수령지를 제안한다. `이 수령지 사용` 또는 `다른 수령지`를 직접 고르며 자동 제출하지 않는다. 현재 배송업체·지점·요금을 사용하고 다른 경매의 직수령 장소는 제안하지 않는다.
- 구매자·업체 상단 이용안내를 제거했다. 업체 페이지에서만 현재 참여 업체의 이름·문의 연락처를 제공하고, 연락처 팝업은 닫기·바깥 클릭·Escape로 닫는다.
- 업체 계좌 최초 등록 화면은 설정을 먼저, 등록 이후에는 구매자 처리를 먼저 보여준다.

검증 위험도: 배송 상태·저장 데이터·인증된 페이지 응답 변경을 포함하므로 release 수준으로 분류했다. 이번 범위는 로컬 검토이며 배포와 실제 발송은 실행하지 않았다.

실행 결과:

- `npm run check`: 통과.
- `npm test`: 517개 통과. 기존 문구에 고정된 검사 1개를 새 문구에 맞춘 후 전체 통과했다.
- PC 저장소 `python -m unittest discover -p "test*.py"`: 189개 통과.
- 최종 UI 수정 후 구매자·업체·설정 API·페이지 인접 검사: 77개 통과.
- 로컬 Chrome 45개 화면 조합: 검사한 넘침·대비·입력 크기·컨트롤 이름·스크립트 오류 없음.
- 추가 실화면 검사: 기존 수령지 사용/다른 수령지, 직접 결제방법 저장, 긴 업체 연락처의 320/390px 표시, 팝업 닫기, 기존 카드 안내 취소 확인, 최초 계좌 등록 화면 통과.

회귀 범위에는 중복·경합·오래된 요청·재시작·원자적 저장 실패·확인/발송 상태 잠금·다른 전화번호와 경매 간 조회 격리·지점 폐지·요금 재계산을 포함했다. 로컬 UI 미리보기의 저장은 가상 메모리 자료이며, 실제 API 검증은 별도의 임시 SQLite 데이터로 수행했다. 운영 반영 후의 읽기 전용 검증과 실기기 Safari 검증은 미실시다.

## 업체 출품 내비게이션 — 로컬 미리보기

`출품 개체 / 낙찰·정산 / 업체 정보`를 하단 메뉴로 분리했다. 경매 전에는 출품이 첫 화면이다. 미등록 업체는 최초 진입에 연락처·계좌 등록 창을 보되 건너뛰고 초안을 작성할 수 있다. 검토 요청 전에는 필수 업체 정보를 등록한다. 등록 완료 안내 행은 목록에서 제거하고, 개체 편집 중에는 메뉴 대신 저장·검토 요청 버튼을 고정한다. 동작 범위와 검증은 `VENDOR_ENTRY_PROPOSAL.md`에 기록했다. 운영 업체 페이지에는 아직 이 구조를 배포하지 않았다.

## 구매자 하단 메뉴 — 로컬

첫 등록은 순서대로 진행하고, 저장 이후 `내 개체 / 배송·결제` 두 메뉴를 보여준다. 배송과 결제는 같은 거래의 후속 행동이므로 한 화면에 유지한다. 내 개체에서는 현재 경매와 A/B 식별번호를 유지하고 사진이 있는 개체만 사진 보기를 제공한다. 변경 중인 정보나 추가 낙찰 미저장 상태에서는 등록 화면을 유지한다. 탭 이동 자체는 저장 요청을 만들지 않는다.

320/390/520px, 200% 확대, 최초 등록·추가 낙찰·미저장 변경·이미지 실패·포커스 복귀를 독립 로컬 브라우저에서 확인했다. 관련 단위 테스트 25개 통과. 실제 사진 API 연결과 과거 경매 통합은 별도 작업이며 운영에는 아직 배포하지 않았다.

후속 연결: 기존 결제 API의 개체·부·모 사진을 구매자·업체 공통 뷰어로 연결했다. 유효한 개인 링크는 보관된 경매의 개체와 거래 내역을 읽기 전용으로 표시한다. 사진 저장·공통 부모 참조, 장기 개인 보관함, 과거 경매 소유권 통합은 계속 별도 작업이다. 최신 검증 결과와 정확한 범위는 `PRODUCT_EXPERIENCE_RENEWAL.md`에 기록한다.

구매자 내비게이션은 로컬에서 검토할 수 있으며 운영 배포 전이다. 최초 수령지·결제 등록은 순서형 흐름을 유지하고, 등록 후에는 `내 개체 / 배송·결제` 두 메뉴로 사진·부모 정보 조회와 거래 진행을 나눈다. 업체 메뉴와 개수를 맞추기 위해 구매자에게 별도 설정 메뉴를 추가하지 않는다.
