# 통합 운영 기준

2026-11-08

## 기준 진입점

- 운영자: `/main`. 전체 일정에서 회차 선택 → 해당 업무의 세부 메뉴.
- 업체: `/vendor-access.html`. 인증 → 내 경매 → 출품 / 낙찰·정산.
- 처음 인증한 번호에 연결된 업체가 없으면 `참가할 경매 선택` → 업체 선택·등록 → 출품으로 이동한다. 기존 참가 업체는 `내 경매`를 유지하고 `다른 경매 참가`로 추가 진입한다.
- 지역 선택과 전크자 홍보 원고는 전국크레자랑을 선택한 흐름에서만 표시한다. 씨랩·쭌이네는 해당 방송의 업체 목록으로 바로 들어간다.
- 기존 전용 링크·보관 회차 URL은 유지한다. 로그인 권한을 새로 합치거나 업체명을 기준으로 연결하지 않는다.

## 화면 규칙

- 운영 메뉴는 일정·홍보 / 출품·경매 준비 / 방송 도구 / 낙찰·배송·정산 / 업체·접속 관리 / 설정.
- 같은 업무의 세부 화면은 상단 메뉴로 이동한다. 선택한 회차와 보관 범위는 유지한다.
- 전체 일정의 회차 선택은 송출 전환과 별개다. 날짜가 지난 방송도 입금·배송·정산 화면에 접근할 수 있다.
- 업체 홈은 오류 → 확인 필요 → 출품 접수 → 응답 대기 → 낙찰 내역 순으로 정렬한다. 출품과 정산이 동시에 남으면 둘 다 표시한다.
- 로그인 후 경매 목록은 기존 인증 결과의 회사 및 참여 권한만 사용한다. 임의 경매 선택으로 업체가 생성되거나 권한이 생기지 않는다.
- 참가 목록은 활성 경매 중 출품 접수가 열린 경매만 노출한다. 날짜가 지난 경매·마감된 접수·전크자 개별 회차는 신규 참가 선택에서 제외한다. 선택과 조회는 권한을 만들지 않는다.
- 일반 경매의 신규 등록은 인증한 대표 번호와 명시적인 대표 연결 확인으로 해당 경매에만 생성한다. 미리 등록한 업체는 대표 번호·계좌·거래/출품 이력·다른 경매 연결이 없는 빈 업체만 처음 연결할 수 있다. 기존 대표 번호나 공유 업체 연결은 바꾸지 않으며 업체 이름으로 과거 기록을 합치지 않는다.
- 상태를 읽지 못하면 완료나 0건으로 표시하지 않는다.
- 본문 설명은 상태·건수·다음 행동 위주로 한 줄. 가입 안내 등 부가 설명은 접힌 도움말에 둔다.

## 운영 방식

- 파르게 접수의 `보내는 분`은 출발 거점과 별개이며 회차별로 저장한다. 기존 16px 입력·44px 버튼·중립 카드 토큰을 사용하고 모바일에서는 저장 버튼을 다음 줄에 둔다. 저장 결과와 오류는 입력란 바로 아래 표시한다. 이름 변경은 새 접수에만 적용하며 과거 접수의 보내는 분은 유지한다.

출품 검토의 ‘접수·담당 설정’에서 경매별 자동 마감, 배송 담당, 정산 담당을 지정한다. 담당은 안내용이며 계좌, 실제 정산 계산 및 권한을 변경하지 않는다. 씨랩 기본 안내는 주관 업체 배송 / 크레용 정산이다. 전크자는 기존 방송일별 출품 절차를 유지한다.

자동 마감은 서버가 매 요청마다 판정한다. 스케줄러가 채널을 삭제·보관하거나 정산을 완료시키지 않는다. 마감된 출품의 조회와 운영자 검토는 유지된다. 전크자 공통 접수 채널에는 전체 일괄 마감일을 설정하지 않는다.

## 유지하는 원장과 경계

낙찰자 결제, 업체가 주관사에 보내는 정산금, 회차 총정산표는 같은 업무 메뉴에서 접근하지만 각 원장과 계산을 유지한다. 배송 담당 안내로 업체의 재무 내역을 숨기거나 다른 주관사의 계좌로 변경하지 않는다. 공유 업체 정보와 회차별 거래 기록은 분리한다.

## 시각 기준

기존 운영 화면의 어두운 중립색·금색 강조, 업체 화면의 흰색·파란색 강조를 유지한다. 모바일 버튼은 최소 44px, 입력은 16px 이상. 상태는 색만 사용하지 않고 문구·건수를 함께 제공한다. 760px 이하 운영 세부 메뉴는 기본 선택 상자, 일정은 한 열로 표시한다. 1440px 미만은 전체 메뉴를 접어 본문 폭을 확보하고, 그 이상은 224px 사이드바를 유지한다.

## 추가 통합 시 지킬 경계

이번 통합은 기존 화면·권한·원장을 공통 동선으로 묶는다. 별도 원장 이관, 회차 복제 방식 변경, 임의 업체 자동 연결, Google 개인 달력 동기화, 낙찰·배송·정산 자동 완료는 수행하지 않는다. 해당 변경은 실제 원장의 대조 및 별도 검증이 필요하다.

## 검증 기록

### 2026-11-11 신규 업체의 경매 선택 진입

- 공통 로그인과 씨랩 출품 흐름에서 전크자 지역 선택·홍보 원고를 분리했다. 기존 공통 컴포넌트와 색상·글꼴·버튼 크기를 유지하고 안내는 한 문장으로 제한했다.
- 가상 SMS와 격리 SQLite에서 첫 인증 → 씨랩 → 미연결 크레하니 → 대표 번호 연결 → 업체 정보 저장 → 개체 임시 저장 → 내 경매 재진입을 확인했다. 전크자 선택 시에만 지역 선택과 홍보 링크가 나타난다. 실제 카카오 OAuth와 실제 문자 발송은 이 테스트에 포함하지 않았다.
- 390px 업체 홈과 320px 경매 선택을 실제 브라우저에서 확인했다. 320px에서 문서 가로 넘침이 없고 경매 선택 버튼 높이는 90.5px이다. 새로운 모션이나 색상은 추가하지 않았다.
- 전체 JavaScript 2,010개와 Python 110개, 추가 UI 회귀 2개 및 저장 실패 회귀 1개 통과. 번호 오인 연결 차단, 동시 최초 연결, 중복 등록, 마감 후 요청, 재시작, CSRF, 저장 실패 후 재시도와 조회 시 무변경을 검사했다. `npm run check`와 UTF-8·diff 검사를 통과했다.
- 실제 업체 번호·낙찰·정산·출품 데이터는 테스트로 변경하지 않았다. 별도 데스크톱 저장소 또는 통신 계약 변경은 없다.

### 2026-11-08 운영 화면 반응형 구조 개선

- 공통 운영 화면은 화면 높이에 맞추고 본문이 남은 공간을 사용한다. 바깥 문서와 작업 문서의 중첩 세로 스크롤을 제거한다. 기존 도구의 iframe 격리는 유지하며 송출 배치 미리보기의 고정 캔버스를 업무 화면 전체 축소와 혼동하지 않는다.
- 모바일에서는 회차 이름·변경 버튼을 제목 아래에 두고 새로고침은 더보기에 넣는다. 중복 하위 메뉴를 숨기며 기존 배송 요약의 읽기 기능은 상위 낙찰·배송·정산 메뉴에서 접근한다. 개체·업체 목록은 기존 카드 반응형을 활용하고 입력·조작 크기를 보강한다.
- 총정산은 760px 이하에서 내역별 접힘 카드로 표시한다. 큰 화면·인쇄·엑셀은 표를 유지하고 금액 계산과 자료 범위는 동일하다. 새로고침 실패 시 카드에서도 이전 금액을 지운다.
- 브라우저 확인: 320px 개체 목록·편집 창·참여 업체, 390px 홈·메뉴·정산 카드 펼침·방송 배치, 768px 및 1440px 개체 목록. 모바일 업무 상단은 약 148px이며 320px 바깥 문서와 작업 문서에 가로 넘침이 없다. 1280px에서는 접힌 메뉴로 본문 전체 폭을 확보한다.
- 자동 회귀 검사에서 모바일 메뉴의 수정 취소 보호·회차 유지, 화면 폭 변경 시 단일 버튼 이동, 정산 카드의 문자 이스케이프·금액 동일성·실패 후 초기화를 확인한다. 실제 휴대폰 키보드와 스크린리더, 모든 기존 하위 도구의 세부 상태를 검증한 것은 아니다.
- JavaScript 전체 1,994개, Python 110개와 capture-agent 3개 통과. `npm run check`, 변경 스크립트 구문 검사, `git diff --check` 통과. 별도 데스크톱 저장소 및 통신 계약 변경은 없다.
- 디자인 탐지기의 `side-tab` 경고 1건은 정산 접힘 표시의 7px 화살표 테두리이며 카드 장식이 아니다. 실제 렌더링에서 확인했다. CSS/JS 정적 검사의 색 대비·작은 글씨 탐지는 제한적이므로 렌더 검수를 함께 사용했다.

### 2026-11-08 첫 화면 집중도 개선

- 업체 홈은 진행·확인할 경매와 접힌 지난 경매로 나눈다. 오류, 등록, 출품, 응답 대기, 미정산·검토 필요가 있으면 접지 않는다. 참여 업체 배송은 완료 여부를 이 요약으로 증명할 수 없으므로 낙찰이 있는 방송을 계속 노출한다. 지난 경매는 완료 처리가 아니며 모든 기존 내역으로 이동할 수 있다.
- 배송·정산 담당은 짧은 접힘 영역으로, 홍보 원고는 로그인 후에도 접근 가능한 작은 링크로 유지한다. 지난 방송의 주 행동은 낙찰·정산이다.
- 낙찰자 최초 등록에 수령지 → 결제 단계를 표시한다. 버튼은 ‘수령지·결제 방법 저장’으로 명시하고 저장 후 실제 결제 안내로 전환한다. 금액 계산과 결제 상태 전이는 변경하지 않는다.
- 운영 홈은 선택한 방송의 업무 버튼을 전체 일정 위에 놓는다. 방송 준비 화면의 출품 0 표시는 실제 접수 수량과 혼동되므로 일정 요약에서 제거한다. 기존 색상, 글꼴, 링크 및 회차 범위를 유지한다.
- 검증: JavaScript 전체 1,993개, Python 110개와 capture-agent 3개 통과. `npm run check`, 변경 JavaScript 구문 검사 및 `git diff --check` 통과. 별도 데스크톱 저장소는 확인되지 않았으며 통신 계약 변경은 없다.
- 격리된 브라우저에서 업체 홈·지난 경매 펼치기, 운영 홈·지난 방송 선택, 낙찰자 수령지 선택·저장·새로고침을 확인했다. 업체·낙찰자 320px에서 가로 넘침이 없고 운영 홈 320px에서도 업무 버튼을 사용할 수 있다. 200% 확대와 실제 기기/스크린리더는 별도 검증하지 않았다.
- 디자인 탐지기의 `order-details` 여백 경고 1건은 기존 가로 구분선 영역이다. 실제 화면의 56px summary 및 공통 24px 바깥 여백을 확인했고, 테두리 카드로 변경하지 않았다. 이번 검수 범위는 세 주요 진입 흐름이며 모든 기존 하위 화면의 전면 검수를 뜻하지 않는다.

- `npm run check`, 병합 후 JavaScript 테스트 1,992개, 이 저장소의 Python 테스트 110개 통과. 기존 구매자 라이브러리 테스트의 비동기 대기가 전체 병렬 실행에서 한 번 실패했으나 개별 재현은 통과했고, 전체를 `--test-concurrency=2`로 실행해 1,992개 통과를 확인했다.
- 인증된 참여 업체만 조회, 회차 간 격리, 읽기 요청 무변경, 저장 충돌, 재시작 유지, 오류 시 확인 필요 표시, 접수 마감 경계를 검사했다.
- 격리된 테스트 데이터로 운영 홈, 회차별 업무 이동, 씨랩 출품 진입, 접수·담당 저장을 브라우저에서 확인했다. 업체 홈 320px에서 가로 넘침이 없다.
- 별도 데스크톱 저장소는 확인되지 않아 그 저장소의 테스트는 실행하지 않았다. 데스크톱 통신 계약은 변경하지 않았다.
