# 회차 마감·안내

주관사 정산 페이지에는 미정산 업체 LMS 안내·재전송을, 배송 관리에는 선택 낙찰자/수령지 미입력자 LMS 안내와 업체별 구매자 결제완료 처리를 둔다. 운영자가 대상을 선택하고 실제 금액·문구를 확인한 뒤 실행한다. 운영자 인증과 기존 회차 범위를 유지한다. 업체용 공유 코드 화면에는 운영자 문자 기능을 노출하지 않는다.

## 처리와 발송

- 결제는 기존 `confirmBuyerPayment`를 재사용하며 현재 금액·배송·결제수단을 다시 대조한다. 회차 및 요청 ID를 고정하고 중복·재시작 시 완료 처리를 반복하지 않는다. 일부 신고, 미등록, 변경 요청, 카드 취소 확인 필요 건은 제외한다.
- 문자 계획은 15분 동안 유효하다. 모든 수신자의 최신 정보와 중복 상태를 다시 확인한 후 계획 결과와 발송 대기를 같은 저장 트랜잭션으로 기록한다. 작업자는 발송 직전 금액/배송/낙찰 변경과 구매자 링크 폐기를 다시 검사한다.
- 24시간 내 재안내는 별도 체크가 필요하다. 대기/재시도/결과 불명확 건은 중복 발송하지 않는다. 접수 후 응답 저장 실패 및 불명확 응답에 대한 기존 큐 보호를 유지한다.
- 알리고 API로 LMS를 발송한다. 웹 로그인/발신번호 OTP를 자동 입력하는 방식이 아니다. API 키·발신번호·발송 잔액의 기존 유효성이 필요하다. 일반 거래 SMS의 90바이트 상한은 그대로 유지한다.
- 보관 채널에서 새 운영자 안내 두 종류만 큐를 처리한다. 과거의 다른 알림을 갑자기 재발송하지 않는다. 웹에서 수동으로 보낸 내역은 이 기능의 중복 방지 이력에 포함되지 않는다.

## 검증

- 변경 위험: shipping/payment/outbox state 및 운영 배포.
- `node --test test/closing-operations.test.js`: 9 passed. 관리자 경계, 회차 격리, 미입력/부분 신고 제외, 중복/동시 요청, 재시작, 오래된 금액/수령지, 기간 만료, 저장 실패 원자성, 보관/다음 회차를 확인했다.
- notification suite에 운영자 LMS 범위/길이 및 보관 채널 큐 필터 회귀 검증을 추가했다.
- `npm run check`: passed. 새 운영 모듈·UI·preview의 별도 `node --check`도 통과했다.
- `npm test`: 1,893 passed, 0 failed (화면 분리 후 재검증).
- `test/closing-tools-ui.test.js`: 배송 화면의 구매자 안내/결제 전환, 주관사 화면의 업체 안내 전용 동작, 회차 링크, 역할별 이력 및 권한 해제 검증. 관련 organizer UI 테스트 포함 27개 통과.
- 실제 organizer 페이지에서 미정산 업체 선택·LMS 미리보기, 배송 페이지에서 가상 결제 처리 및 낙찰자 안내 탭을 확인했다. 390px 정산 미리보기에서 가로 넘침이 없음을 확인했다.
- UTF-8 strict decoding/replacement-character scan 및 `git diff --check`: passed.
- 가상 SQLite + 실제 shipping.html을 로컬 브라우저에서 확인: 결제완료 결과, 낙찰자 선택/문자 접수, 업체 정산 문자, 검색 빈 상태, 320px 폭, 미리보기 키보드 포커스. 실제 수신자에게 테스트 발송하지 않았다.
- 데스크톱 앱 계약은 변경하지 않았다. 로컬에서 별도 데스크톱 저장소를 찾지 못해 해당 저장소의 전체 테스트는 실행하지 못했다.

운영 검증은 배포 후 실제 회차의 읽기 전용 목록과 발송 설정 상태만 확인한다. 실제 문자 전송 성공 및 최종 수신 결과는 운영자의 첫 발송 이후 확인할 수 있다.
