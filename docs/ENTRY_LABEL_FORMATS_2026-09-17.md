# 식별 라벨 형식 선택

범위: 출품 검토의 식별 라벨 미리보기, 브라우저 인쇄, PC 앱 인쇄 연결. 위험도: release(웹→PC 인쇄 형식 계약 추가). 경매/낙찰/배송 상태와 알림 발송은 변경하지 않는다.

- 기존형: 50×30mm, 업체명·식별 번호·성별/체중·부모명·출품 번호 유지.
- 접는형: 같은 용지를 30×50mm 세로 방향으로 사용. 30×25mm 두 면에 업체명·식별 번호를 반복하고 중앙 점선을 인쇄한다. 두 정보 묶음을 중앙에서 약 1mm씩 바깥으로 옮겼다.
- 웹 미리보기는 세로로 표시한다. B1용 비트맵과 브라우저 인쇄는 90도 회전해 기존 50×30mm 급지 영역 안에 배치한다.
- 선택은 `creo.entry-label-format`에만 저장한다. PC 앱의 기본 낙찰 라벨 설정은 수정하지 않는다.
- 기존 요청은 그대로 동작한다. 접는형은 `format: fold`와 브리지의 `identificationLabelFormats` 지원 확인이 필요하다. 구버전 앱에 접는형을 보내 기존형으로 잘못 출력하는 것을 차단한다.
- 제출 중 형식 변경/중복 클릭을 차단하며, 기존의 최신 출품 정보 검증을 두 형식 모두 사용한다.

## 검증

- `node --test test/entry-label-format.test.js test/entry-batch.test.js`: 18개 통과. 형식 전환, 저장/재진입, 제출 중 잠금, 중복 클릭, 구버전 앱 및 오래된 데이터 차단.
- `python -m unittest test_entry_identification_label`: 8개 통과. 두 면 반복, 중앙 여백/점선, 긴 번호, 90도 회전, 큐 직렬화, 잘못된 형식의 전체 배치 거부.
- 접는형 요청 전후에 실제 낙찰 작업 생성 함수를 호출해 기본 설정, 낙찰자·전화번호·금액·성별·체중이 유지되고 배송 작업도 배송 형식을 유지함을 확인.
- `npm run check`: 통과. `npm test`: 757/757 통과.
- `python -m unittest discover -p "test*.py"`: 200/200 통과.
- 실제 CSS 인쇄 규칙의 로컬 화면 증명: 회전된 두 라벨이 각각 50×30mm 영역 안에 맞고 중앙 점선은 25mm 위치, 마지막 장에 불필요한 페이지 나눔 없음.
- B1 비트맵: 576×360, 세로로 돌려 보는 결과 360×576. 기본/긴 업체명 이미지 시각 확인.
- UTF-8 replacement-character 검사 및 diff whitespace 검사 통과.

실물 용기 부착/실제 출력은 실행하지 않았다. PC 앱이 이미 실행 중이면 새 브리지 기능을 읽도록 재실행이 필요하다. 운영 배포 후 health/static 검증 결과는 로컬 릴리스 기록에 별도 보관한다.
