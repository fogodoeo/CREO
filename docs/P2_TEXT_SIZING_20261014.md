# P2 글자 크기와 자동 가로폭 — 2026-10-14

## 범위

전국크레자랑 P2 송출 배치의 글자 크기 입력 → 미리보기 → 저장 → 재접속 흐름. 기존 HTML/CSS/JavaScript와 배치 저장 API를 사용한다. `AGENTS.md`, `docs/LIVE_RELIABILITY_CHECKLIST.md` 및 better-interface의 6개 영역을 기준으로 검토했다. 새로운 모션은 추가하지 않았다. P1/P3, 낙찰 처리, 결제, 다른 채널 테마는 변경 범위 밖이다.

위험도: **Release**. 선택 설정이 서버에 저장되고 공개 송출 화면에 전달되므로 저장·재시작·권한·채널 분리와 실제 화면을 검증했다.

- `node --test test/broadcast-text-layout.test.js test/national-broadcast-panels.test.js test/broadcast-bid-motion.test.js test/studio-layout-draft.test.js`: 16개 통과.
- `node --test --test-name-pattern="P2 text sizing persists" test/platform-api.test.js`: 1개 통과. 비인증 저장 차단, 반복 저장, 부분 저장, 재시작, 다른 채널 분리, 경매 상태·입찰 불변 검증.
- `node --test --test-concurrency=4` (bundled NODE_PATH, 호스트에서 임시 DB/로컬 서버): **1,139개 통과**.
- 데스크톱 `python -m unittest discover -p "test*.py"`: **203개 통과**. 기존 SQLite ResourceWarning / Pillow deprecation 경고 발생.
- 첫 병렬 실행은 promo-partners 파일 프로세스가 실패했지만 개별 테스트 5개는 통과했다. 제한 환경 재실행은 localhost 연결 EACCES로 실패했다. 호스트에서 동시 실행 수를 4로 제한한 전체 실행은 위와 같이 통과했다.
- `git diff --check`, 변경 파일 strict UTF-8 및 U+FFFD 확인: 통과.
- 실제 화면: 150%에서 개체명 69px, 입찰명 66px. 자동 폭을 수동 40%로 변경해도 66px 유지. 숫자 입력과 슬라이더 키보드 조절(150→155%) 연동. 저장·새로고침 후 150%와 자동 폭 유지.
- 실제 화면: 입찰 없음 1행 `입찰 대기`, 입찰자 1명 1행, 2명 2행. 낙찰 자막 459px 폭에서 잘림 없음. 250% 긴 텍스트는 우측 98% 이내에 표시.
- 320×812 편집 화면에서 가로 넘침 없이 입력 컨트롤 접근 확인. 브라우저 자체 200% 줌은 별도 검증하지 않았다.
- UI 콘솔에 원인이 특정되지 않은 MutationObserver observe 오류가 기록되어 있었다. 조절·저장 흐름은 완료했고, 이를 새 기능의 무오류 근거로 사용하지 않았다.

## 같은 요청에서 수정한 운영 데이터

사용자가 지정한 `전크자1014.xlsx`의 Sheet1 E열(파일 헤더: 모프)을 송출 비고로 반영했다. 38개체 중 차이가 난 17건을 수정했고 38건 전체를 재조회하여 대조했다. 빈 셀은 비고도 비웠다. 기존 업체 설명과 `패널 개체` 표시는 넣지 않았다. 각 개체의 최신 버전으로 저장하고 응답에서 비고·수정시각 외 필드가 바뀌지 않았음을 확인했다. 사진, 부모 사진, 입찰, 낙찰 정보, E01/E02 수수료 면제 속성은 보존했다.

`REPSODY 렙소디` 업체명과 연결된 A03/A12/B03/B12의 표시 업체명을 `렙소디`로 변경했다. 단발성 보정 스크립트의 합성 데이터 회귀 테스트 7개 통과. 운영 기록은 테스트 입력으로 쓰지 않았다.

## 한계 및 판정

글자를 최대로 키우거나 여러 요소를 같은 위치로 배치할 때 요소 간 겹침을 자동 해결하지는 않는다. 운영자가 미리보기를 보고 위치를 조절하는 기존 방식이다. OBS의 실제 설치 버전은 직접 확인하지 않았으며, 새 정적 파일을 적용하려면 기존 브라우저 소스 새로고침이 필요하다.
