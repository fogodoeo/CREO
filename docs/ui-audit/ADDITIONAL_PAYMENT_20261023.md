# 추가 낙찰 결제 흐름 · 2026-10-23

## 범위

기존 결제 확인 대기 → 같은 업체 추가 낙찰 → 기존 결제 확인 → 추가 배송정보 저장 → 추가 계좌이체/카드 안내 → 낙찰자 완료 요청 → 업체 확인을 점검했다. better-interface의 접근성·구조·문구·글자·색·UI 원칙을 기존 HTML/JS/CSS에 적용했다. 결제 완료 후 배송비 변경·환불은 이번 범위에 포함하지 않는다.

위험도는 high(배송 저장 시 카드 안내의 생명주기), 배포는 release다. 가격·수수료·정산 계산과 결제 확인 금액/버전의 서버 검증 계약은 유지한다.

## 재현한 문제와 개선

| 영향 | 재현 | 개선 |
| --- | --- | --- |
| HIGH | 업체 카드 안내 창이 전체 207,000원 중 100,000원을 이미 결제했어도 207,000원으로 표시했다. | 미결제 107,000원을 안내 금액으로 표시하고 전체/확인 완료 금액을 분리한다. API의 expectedAmount는 기존대로 전체 금액을 보내 동시성 검증을 유지한다. |
| HIGH | 최초 100,000원만 확인 요청한 뒤 추가 100,000원이 낙찰되면 낙찰자 화면에서 200,000원을 확인 중이라고 표시했다. | confirmationDue에 해당하는 확인 요청 금액과 추가 예상금액을 구분한다. 배송비 변경 시에는 기존 요청액과 변경 후 남은 금액을 별도로 표시한다. |
| HIGH | 완납한 카드 안내도 추가 낙찰 시 취소 대상으로 표시돼 새 안내를 등록하지 못했다. | 미결제 배송 행의 안내를 우선 사용하고, paid 행의 안내는 추가금 발생만으로 취소 대상으로 만들지 않는다. 아직 미결제인 안내의 금액 변경은 기존 취소 절차를 유지한다. |
| HIGH | 응답이 불확실한 카드 안내를 다시 열면 요청 본문은 이전 금액인데 새 데이터의 금액이 화면에 표시됐다. | 재시도할 요청과 당시 표시 금액을 함께 보존한다. |
| MEDIUM | 기존 결제 확인 뒤 추가 낙찰을 저장해야 하는데 제목이 ‘결제 방법을 선택해 주세요’였다. | ‘추가 낙찰 내역을 확인해 주세요’와 저장 후 금액 확정 안내를 표시한다. |

새 회귀 4개가 수정 전 금액 표시에서 실패했고, 완료된 카드 안내의 추가 낙찰 테스트 2개도 수정 전 취소 요구로 실패했다. 수정 후 모두 통과했다.

## 자동 검증

- `node --test test/vendor-payment-work.test.js test/buyer-checkout-flow.test.js test/payment-confirmation.test.js test/checkout-notification-atomicity.test.js test/checkout-change-requests.test.js test/checkout-core.test.js test/checkout-actions.test.js test/gateway-server.test.js`: **99 통과, 0 실패**.
- `npm test -- --test-concurrency=4`: 최종 **1,799 통과, 0 실패**.
- 데스크톱 `python -m unittest discover -p "test*.py"`: **279 통과**.
- `npm run check`, 변경 파일 10개 strict UTF-8/스크립트 구문 검사 통과.
- 최초 전체 실행의 실패 2개: 분리 실행하는 기존 quote 테스트에 새 함수 의존성 누락(테스트 환경 수정), 임시 로컬 게이트웨이 포트에 대한 fetch의 `bad port`(대상 재실행 통과). 최종 전체 실행은 깨끗하게 통과했다.
- 신규 서버 회귀는 링크형/별도 앱 카드 안내, 저장 실패 시 원자적 복구, 중복·동시 저장, DB 재시작, 이전 확인 금액/시각/요청 ID 보존, 추가 미결제 안내의 취소 차단 유지, 다른 채널 독립성을 확인한다.

## 실제 화면 검증

`VENDOR_PAYMENT_PREVIEW_ADDITIONAL=1 VENDOR_PAYMENT_PREVIEW_PORT=4424 node tools/vendor-payment-preview.cjs`의 가상 업체·격리 SQLite만 사용했다. 외부 결제 앱을 열거나 실제 메시지를 발송하지 않았다.

실제 320px 화면에서 다음을 완료했다.

1. 업체 A는 226,000원 확인 대기와 추가 예상 57,000원으로 구분됐다.
2. 업체 B는 기존 107,000원 결제 후 새 카드 안내를 바로 등록할 수 있었다. 창에서 이번 카드금액 87,000원, 전체 194,000원, 확인 완료 107,000원이 표시됐다.
3. 카드 안내 저장 응답 한 번 유실을 주입했다. 기존 클라이언트의 같은 요청 재시도로 복구됐다. 낙찰자 요청과 업체 확인도 87,000원이며 완료 후 194,000원으로 표시됐다.
4. 업체 A의 원래 226,000원만 확인한 뒤 낙찰자에게 추가 낙찰 저장 단계가 표시됐다. 저장 후 57,000원 입금 안내→확인 요청→업체 확인을 완료했다.
5. 마지막 낙찰자 화면은 업체 A 283,000원, B 194,000원, 합계 477,000원 ‘결제가 완료됐어요’로 표시됐다.

320px의 카드 안내 창에서 모든 입력·하단 버튼과 전체/확인 금액이 겹치지 않았다. 기존 글자색과 버튼색을 재사용했다. 200% 확대와 전체 키보드·화면 낭독 검사는 아직 별도 남아 있다.
