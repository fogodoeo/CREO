# 주관사 정산 화면 — 로컬 재검토

2026-09-12. 전체 페이지 개선 목표의 일부 진행 기록이다. 운영 배포·실제 고객 자료 변경·알림 발송은 하지 않았다.

## 확인한 흐름

운영 HTML/CSS/JS와 실제 `createPlatformApi`, 임시 SQLite로 확인했다. 가상의 업체·예금주·배송지·계좌만 사용했으며 알림 워커와 외부 인증/저장소를 연결하지 않았다. 브라우저 외부 요청은 차단했다.

- 계좌 미등록 시 입력, 등록 후 요약/수정
- 업체 요청 확인, 직접 일부 입금, 추가 입금, 취소 이력 보존
- 배송지 미입력 업체와 배송비 상세
- 초과 입금 업체와 다른 업체의 미입금 잔액
- 최초 조회 장애, 최신 조회 장애, 늦은 응답, 권한 오류, 저장 응답 유실
- 모바일 320/390/520px의 긴 업체명·예금주와 팝업

## 재현과 수정

1. 최초 GET 장애에서는 콘텐츠와 새로고침 버튼이 모두 숨겨져 있었다. 로컬 브라우저에서 재현 후, 오류 문구와 `다시 불러오기`를 추가했다. 성공하면 이전 오류를 지운다. 링크 없이 직접 HTML에 접근하면 전용 링크 안내만 표시한다.
2. 열린 입금 폼의 POST가 401을 반환해도 업체명과 입금액이 계속 보였다. 권한 오류 시 팝업을 닫고 계좌·업체·입금 폼을 비우며 자동 재조회도 멈춘다. 운영자 접근은 로그인 화면으로 돌아간다. UI 검사의 401은 주입한 응답이며, 실제 권한 범위는 별도의 API 회귀에서 확인한다.
3. 늦은 이전 조회의 오류에는 요청 순서 검사가 없었다. 성공과 실패 모두 순서를 검사하고, 저장 시작 전에 이전 읽기를 무효화한다. 오래된 성공/401이 최신 화면을 덮지 않는다.
4. 갱신 실패 시 기존 금액은 읽을 수 있지만 새로운 입금 확인은 최신 조회 후에 가능하다. 저장이 끝난 뒤 조회만 실패한 경우에는 `입금 확인 완료 · 최신 내역 확인이 필요해요.`로 구분한다. 모호한 POST 실패의 재시도는 같은 requestId를 보존한다.
5. 초과 입금 업체도 `입금 완료 / 0원`으로 나왔다. `초과 입금 / 10,000원 초과`처럼 표시하고 상단에 초과 입금 합계를 별도로 노출한다. 상단 주요 금액은 **업체별 미입금 합계**이며 다른 업체의 초과 입금으로 상계하지 않는다. 실제 합계 계산이나 원장 저장 로직은 변경하지 않았다.

기존 한 팝업에서 입금액·오늘 날짜를 미리 채우는 방식과 직접 수정, 메모 선택, 바깥 클릭 닫기는 유지한다. 데이터가 없는 사진/추가 카드 등은 넣지 않았다.

## 검증

위험도 **high**: 배송비 입력 화면의 조회·오류·재시도 상태 변경. API/영속 형식/PC 계약 변경은 없다.

- `node --test test/organizer-bank-ui.test.js test/organizer-recovery-ui.test.js test/organizer-receipts.test.js`: **21개 통과**. 새 회귀 9개. 요청 중복/동시 입력, 재시작, 오래된 총액, 권한 범위, 저장 장애, 취소 이력은 기존 실제 SQLite 검사와 함께 확인했다.
- PC 저장소 `node scratch/checkout-redesign/organizer-recovery-check.cjs`: 실제 Chrome **6그룹 통과**. 320/390/520px, 경매 쿼리보다 주관사 코드 범위 우선, 실제 DB 저장 후 HTTP 응답 유실/동일 요청 재시도를 포함한다. 알림 레코드 0개, 구매자 결제 상태 유지, 중복 입금 없음도 확인했다.
- PC 저장소 `node scratch/verify-organizer-production-ui.cjs`: 기존 실제 화면 경로 통과. 파일명과 달리 운영 서버에 접속하지 않고 임시 DB를 사용한다. 일부 입금→재조회→추가 입금→취소, 업체 요청 확인, 320px, 바깥 닫기 검사다.
- `npm run check`, 별도 `node --check public/organizer-shipping.js`, `npm test`: 구문 검사 및 **서버 644개 통과**.
- `git diff --check`, 변경 HTML/JS/검사의 엄격한 UTF-8 검사 통과. 한글 일괄 재저장은 없다.
- PC 프로그램 변경은 없어 이번 단계에서는 PC 전체 검사를 반복하지 않았다. 이전 단계 PC 189개 결과를 이번 실행으로 계산하지 않는다.

예시/증거는 PC 저장소 `scratch/checkout-redesign/organizer-review-fixture.cjs`, `organizer-recovery-check.cjs`, `organizer-recovery-before.json`, `organizer-recovery-results.json`, `organizer-review-main-390.png`, `organizer-recovery-initial.png`, `organizer-recovery-expired.png`에 있다. 최신 실행 로그는 `organizer-recovery-check.log`, `organizer-recovery-server.log`다. 로컬 미리보기는 18837 포트이며 구체적 접근 URL은 `organizer-review-preview.log`에 기록한다.

## 남은 범위

이 검사는 전체 50개 HTML의 검토 완료를 뜻하지 않는다. 운영자·송출 등 나머지 역할의 실제 연결 점검, 장시간 백그라운드/앱 복귀의 정산 화면 갱신, 계좌 영역의 DOM/시각 순서, 실제 카카오 인앱 브라우저, Linux/운영 배포 검증은 별도다. 서버는 Node 24.18에서 검사했으며 배포 런타임은 Node 22다. 초과 입금의 실제 반환/송금 기능은 추가하지 않았다.
