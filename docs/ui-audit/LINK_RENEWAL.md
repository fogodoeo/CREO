# 만료된 구매자 링크 복구 — 로컬

이전 방식에서는 운영자가 만료 링크에 `새 링크 발급`을 실행하면 주소와 접근 세대가 바뀌어 기존 보관함 연결도 차단됐다. 장기 보관함을 유지하면서 단순 기간 만료를 해결할 수 있도록 기간 연장을 별도로 추가했다.

## 동작

| 동작 | 짧은 주소 | 보관함 연결 | 조건 |
| --- | --- | --- | --- |
| 기간 연장 | 기존 주소 유지, 실행 시점부터 14일 | 유지 | 기간 만료, 운영자 인증, 낙찰 기록 확인 |
| 새 링크 발급 | 새 주소, 이전 주소 차단 | 새 링크로 재연결 필요 | 운영자 인증 |
| 사용 중지 | 기존 접근 차단 | 차단 | 운영자 인증 |

- 운영 배송 화면의 구매자 선택 → 개인 링크 관리에서 기간이 만료됐을 때 `기간 연장`을 주 행동으로 제공한다. 주소 교체와 사용 중지도 별도 버튼으로 유지한다.
- 연장은 세대는 유지하고 revision과 감사 기록만 증가시킨다. 단축 코드 안의 새 서명 토큰·상태·요청별 감사 기록을 한 번에 저장한다.
- 같은 요청 재시도는 한 번만 반영한다. 다른 창의 주소 교체/중지가 먼저 실행되면 오래된 연장 요청을 거절한다. 중지된 주소를 연장으로 되살릴 수 없다.
- 기존에 직접 전달된 만료 서명 토큰은 만료 상태를 유지한다. 복구되는 주소는 `/d/코드`, `/s/코드` 단축 주소다.
- 낙찰/배송/결제/알림 기록은 변경하지 않고 알림을 발송하지 않는다. 보관된 경매는 복구 후에도 읽기 전용이다. 당시 저장된 낙찰자 번호가 없는 보관 기록은 회원 명단으로 추정하지 않는다.
- 구매자 링크를 열 수 없을 때, 기능이 설정된 사이트에서는 오류 화면에 `내 보관함`을 제공한다. 이 버튼에는 만료 코드를 넘기지 않으므로 보관함을 열자마자 같은 실패 연결을 다시 요구하지 않는다. 링크 확인 안내와 재시도도 유지한다.
- 오류 화면에 브랜드·본문 크기·좌우 여백·48px 버튼 정렬을 적용했다. 기존 거래 내용은 표시하지 않는다.

## 검증

위험도 release. 운영 배포/운영 고객 자료 변경/실제 알림 발송 없음.

- `node --test test/buyer-link-access.test.js test/buyer-account.test.js`: 26개 통과. 서명까지 실제로 만료시킨 링크의 복구, 원래 주소 유지, 만료 서명 토큰 차단, 중복·재시작·저장 실패·경합·폐기 후 재시도·보관 경매 읽기 전용·보관함 유지·주소 교체 시 보관함 차단을 검증했다.
- `npm run check`: 통과. `npm test`: 632개 통과.
- PC `python -m unittest discover -p "test*.py"`: 189개 통과.
- 실제 운영 배송 HTML/API/임시 SQLite로 `buyer-link-manager-check.cjs` 통과. 만료 상태·연장 확인·응답 유실 동일 요청 재시도·같은 주소 복구·후속 교체/중지 충돌·320/390/800px·Escape/바깥 클릭/포커스 복귀를 확인했다.
- 실제 개인 보관함 HTML/API/임시 SQLite로 `buyer-library-check.cjs` 통과. 만료 거래 화면에서 기존 보관함으로 이동하고 추가 연결 창이 열리지 않는 경로를 확인했다. 320/390/800px, 좌우 여백과 버튼 정렬을 검증했다. 오류 화면과 운영자 만료 창의 캡처를 직접 확인했다.
- 최종 정렬 수정 후 보관함 브라우저 검사를 재실행했다. UTF-8·인라인 스크립트·`git diff --check`를 통과했다.

이 작업은 기존 낙찰 증거가 있는 거래 링크의 운영자 복구다. 삭제되거나 덮인 원장 복원, 당시 구매자 번호가 없는 내역의 증거 수집, 전체 과거 경매 일괄 이관은 완료하지 않았다. 실제 카카오 계정 설정과 실기기 Safari/카카오톡 앱, 운영 Linux/Supabase 검증은 별도로 남는다.
