# 구매자 로그인 복구·만료 자료 정리

2026-09-12. 위험도 **release**. 로컬 임시 SQLite와 가상 카카오 공급자로 검증했다. 실제 카카오 계정, 고객 기록, 운영 서버 설정과 알림 발송을 사용하지 않았다.

## 문제와 변경

- native form 로그인 실패가 JSON 오류에 머무르던 경로를 앱 재시도로 돌렸다. 취소·만료·시도 제한을 짧게 구분하며 외부 오류 설명은 노출하지 않는다. 원래 거래 링크는 검증된 브라우저 결합 state에서만 복구한다.
- 브라우저마다 하나의 flow 쿠키를 덮던 구조를 서명된 브라우저 결합과 독립된 일회용 state로 바꿨다. 다른 브라우저의 state와 재사용은 거부한다. 기존 진행 중 flow는 만료 시점까지 호환한다. 서명에 임의 접미사를 붙인 쿠키도 새 값으로 교체한다.
- 동일 프록시 사용자를 20회 제한으로 묶지 않도록 브라우저당 20회/10분, 피어당 600회/10분을 적용했다. 전달 IP 헤더로 우회하지 않는다. 버킷은 만료 시 정리하며 최대 2,200개다.
- 재인증 취소 때 기존 세션을 유지하고 `보관함으로`를 제공한다. 이미 만료된 세션은 다시 로그인하되 연결된 개체 기록은 유지한다. 로그인 버튼 연타를 막고 뒤로가기 복귀 시 다시 활성화한다.
- 100행 조회/최대 25개 삭제로 만료 후 하루가 지난 state·세션의 암호화 값만 정리한다. 삭제 직전 같은 값인지 확인하고 변경·복호화 실패 행은 보존한다. 동시 실행은 합치고 저장 장애 후 재시도한다. 서버 종료 시 작업을 기다린다.

## 운영 연결 전 남은 범위

- 실제 카카오 앱/전화번호 동의 권한·콜백과 모바일 카카오톡 간편로그인 SDK를 연결하지 않았다. 카카오싱크는 첫 가입 약관을 합치는 설정이며 비즈니스 채널 등록만으로 켜지지 않는다. 실제 기기·iOS 카카오톡에서 진입/취소/복귀 검증이 필요하다.
- 현재 제한은 프로세스 메모리 범위다. 신뢰 프록시 설정·여러 인스턴스의 공통 한도와 DB CAS/분산 락을 보장하지 않는다.
- 정리는 암호화된 만료 값 제거다. 동기화용 삭제 표시(tombstone), SQLite 파일 공간 회수와 계정/정산 기록 삭제 정책은 별개다. 손상된 행은 자동 삭제하지 않는다.
- 실제 Supabase 원격 삭제/스캔 계약과 Linux 종료 흐름은 미검증이다. 운영 배포와 배포 후 읽기 전용 점검은 하지 않았다.
- 계정 탈퇴·카카오 연결 해제 통지, 과거 낙찰 이관, 사진 보관 정책과 전체 페이지 감사는 계속 남아 있다.
