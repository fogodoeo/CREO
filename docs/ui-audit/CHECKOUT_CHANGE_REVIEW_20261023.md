# 배송·결제 변경 요청 검증 · 2026-10-23

## 범위와 위험도

관리자의 변경 승인·거절 화면, 기존 도도시 승인 화면과의 작업 잠금, 승인·거절 후 낙찰자 표시를 점검했다. 기존 HTML/JS/CSS와 better-interface의 여섯 영역을 적용했다. 기존 API, 회차 선택, 금액 계산, 입금 확인, 환불 정책과 알림 발송 계약은 변경하지 않았다. 프런트엔드 승인 작업의 동시성·실패 복구는 high, 웹 배포는 release 위험도로 검증했다.

## 확인한 문제와 변경

| 영향 | 근거 | 개선 |
| --- | --- | --- |
| HIGH | checkout-changes.html의 기존 승인 핸들러는 자기 행 버튼만 잠그고 새로고침은 허용했다. 성공 뒤 전체 목록을 다시 읽어 다른 요청의 작성 내용을 잃을 수 있었다. | 승인 중 새로고침·다른 변경·도도시 처리를 잠근다. 성공 응답으로 해당 상태를 갱신하고 다른 행의 초안을 유지한다. 읽기 중에도 이전 화면에 대한 승인과 중복 읽기를 막는다. |
| HIGH | 기존 전체 페이지 상단 notice로만 오류를 표시했고, 확인 체크와 거절 사유 누락을 서버 호출 뒤 알렸다. | 해당 요청 안에 지속적인 오류와 재시도 방법을 표시하고 초점·스크롤을 이동한다. 필수 체크·사유는 요청 전 검증하고 오류와 필드를 연결한다. |
| MEDIUM | 처리한 요청까지 변경 전후·거절 설명을 모두 펼쳤다. | 확인 필요 요청을 먼저 보여주고 처리한 기록과 거절 입력을 native details로 접는다. 모바일에서는 변경 전후가 세로로 배치된다. |

응답을 받지 못한 작업은 원래 승인/거절 값으로 재시도하며 반대 작업과 입력 변경은 잠근다. 401/403/409는 최신 내역을 읽어야 다시 처리할 수 있다. 같은 요청의 동일한 변경 내용에만 입력 초안을 복원하며 새 내용에는 기존 확인 체크를 적용하지 않는다. 승인은 환불·외부 카드 취소가 아님을 실제 승인 전 안내한다.

- `npm test -- --test-concurrency=4`: **1,793 통과, 0 실패**.
- 데스크톱 `python -m unittest discover -p "test*.py"`: **279 통과**.
- `npm run check`: 통과. 변경 파일 UTF-8·스크립트 파싱·diff 검사는 배포 전 별도로 확인한다.
- 기존 API 회귀는 동시 승인/거절, 중복 요청, DB 재시작, 저장 실패 원자성, 이미 입금한 상태의 차단, 회차 경계와 별도 업체 독립성을 포함한다.

## 실제 화면

`tools/checkout-change-preview.cjs`의 격리 SQLite·가상 업체·가상 낙찰자·가짜 알림을 사용했다. 운영 자료로 테스트하지 않았다.

- 실제 320px iframe에서 대기 1건/처리 기록 접힘, 변경 전후 세로 배치, 체크 누락 시 해당 입력 초점을 확인했다.
- 승인 저장 후 응답만 503으로 유실: 입력과 체크 유지, 지속 오류·재시도 표시. 재시도 시 하나의 승인 결과와 한 번의 구매자 알림만 기록됐다.
- 두 번째 요청은 사유 입력 후 Tab/Enter로 거절. 응답 유실 후 같은 거절 재시도 성공. 입력은 잠긴 채 보존됐고 반대 승인 버튼은 비활성화됐다.
- 낙찰자 화면 새로고침에서 승인된 직수령/업체별 결제 방법이 표시됐다. 후속 거절 때는 기존 수령지·금액이 유지되고 사유가 표시됐다.
- `../admin-home-review-20261022/checkout-change-error-320.png`: 마지막 실제 오류 화면. 확인 가능한 입력, 초점, 복구 버튼을 포함한다.
- 실제 200% 브라우저 확대·전체 화면 낭독·전체 키보드 경로는 아직 확인하지 않았다. 이미 입금한 뒤 배송비 변경/환불 조정 경로는 이번 작업에 포함하지 않았다.

기존 운영 로그인은 유효했고 main의 업체 정산 메뉴와 채채파파의 현재 정산 계좌 표시를 읽기 전용으로 다시 확인했다. 실제 입금 확인·정산 처리·알림 발송은 수행하지 않았다.

## 배포

배포 결과와 운영 데이터 보존 증거는 배포 완료 후 기록한다. 이 작업만으로 전체 UI/UX 개편이 완료된 것은 아니다.
