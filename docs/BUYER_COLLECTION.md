# 구매자 보관함과 거래 링크 — 구현 경계

2026-09-12. 계정·명시적 거래 연결·낙찰 기록 보존을 로컬 구현했다. 실제 카카오 앱 연결, 과거 고객 자료 이관과 보관/탈퇴 정책은 미완료다. 운영 배포·고객 자료 이관·실제 알림 발송 없이 진행한다.

추가 검증: 다른 탭 로그아웃 후 개체 카드가 남던 문제를 실제 브라우저에서 재현해 수정했다. 계정 변경·페이지 숨김·BFCache 복원에서 목록과 사진/문의 창을 비우고 서버 세션을 재확인한다. [개인 화면 수명 검증](ui-audit/BUYER_SESSION_SCREEN.md)에 8그룹 브라우저 검증과 외부 환경의 한계를 기록했다.

## 확인한 현행 구조

- 구매자 배송·결제 링크는 경매 ID와 정규화한 전화번호의 SHA-256 해시 범위, 기본 14일이다. 링크 서명/관리 키에는 HMAC을 사용한다. 전화번호 해시 자체를 본인확인이나 암호화로 간주하지 않는다. 통상 알림 재발급은 같은 주소의 기간을 갱신한다.
- 보관된 경매의 유효한 구매자 링크는 읽기 전용이다. 과거 거래의 소유자는 저장된 낙찰 기록으로 확인하며 현재 닉네임/회원 명단으로 추정하지 않는다.
- 이전 수령지 제안은 인증된 거래 링크의 전화번호 범위에서 현재 사용 가능한 배송사·수령점을 재검증한다. 선택·결제·저장을 자동 실행하지 않는다.
- `band-membership.js`의 `/verify`는 전화번호가 회원 명단에 존재하는지 확인한다. SMS 소지 인증이나 OAuth 계정 인증이 아니므로 장기 구매자 보관함의 인증 수단으로 재사용하지 않는다.

## 장기 구조의 방향

1. 거래 알림 링크는 그 경매의 배송·결제로 바로 진입하는 용도로 유지한다.
2. 장기 보관함은 별도 계정으로 접근하고 명시적으로 연결된 거래만 보여준다. 계정이 같은 전화번호를 사용한다고 과거 모든 거래의 소유권을 자동 부여하지 않는다.
3. 신규 거래 연결은 본인확인된 계정과 유효한 거래 증거를 함께 확인한다. 과거 이관은 당시 저장된 소유자 근거를 검토하고 연결 기록을 별도로 남긴다. 기존 낙찰 원장을 다시 만들거나 덮지 않는다.
4. 거래 기록·사진의 보관 정책, 링크 만료·폐기, 계정 탈퇴를 분리한다. 링크를 끊거나 보관함에서 숨기는 동작이 정산 기록 삭제가 되어서는 안 된다.
5. 사용자가 카카오 연동과 빠른 진입을 요청했다. 카카오 계정 로그인을 기본 방향으로 삼고, 모바일 카카오톡 간편로그인과 첫 가입 약관을 합치는 카카오싱크 설정을 준비한다. 서버 OAuth와 JavaScript SDK 연결은 로컬 구현했다. 실제 SDK의 웹 로그인 경로는 검증했지만 실제 앱 설정·Android/iOS 카카오톡 전환·싱크 도입은 미완료다.

개체 사진 12개월은 검토 초안이며 자동 삭제 설정이 아니다. 실제 Supabase 저장량·참조 중인 부모 사진·복구/분쟁 처리와 함께 확정해야 한다.

## 구현한 거래 링크 관리

- 운영 배송 화면에서 구매자 선택 → **개인 링크 관리**. 경매·구매자·번호 뒷자리·현재 상태·만료일·현재 주소를 표시한다.
- **기간 연장**은 만료된 기존 주소를 14일 다시 사용할 수 있게 하고 기존 보관함 연결을 유지한다. 주소 교체·중지와 분리했다. 복구 동선과 검증은 [만료 링크 복구](ui-audit/LINK_RENEWAL.md)를 따른다.
- **새 링크 발급**은 현재 경매/구매자의 세대를 증가시켜 주소를 바꾼다. **사용 중지**는 이전 짧은 주소와 서명 토큰의 읽기/저장을 차단한다. 낙찰·배송·결제 행은 변경하지 않는다.
- 일반 알림 준비는 중지된 링크를 자동으로 다시 열지 않는다. 새 링크 발급은 운영자가 명시적으로 실행한다. 해당 동작 자체가 구매자에게 알림을 보내지는 않는다.
- 주소를 바꾸거나 끊기 전에 대상과 결과를 확인하고 실행한다. 응답 유실 재시도는 같은 요청 ID를 쓰며, 다른 창의 더 최근 작업은 오래된 버전으로 덮을 수 없다.
- 변경 이력은 요청별 `buyer_link_audit_v1::<HMAC>` 행에 보존한다. 상태 화면은 최근 20개만 표시한다. `buyer_link_access_v1::<HMAC>`에 상태·세대·리비전을 저장하고, 새 단축 링크와 같은 원자적 upsert에 포함한다.
- 관리자 입금 확인은 새 구매자 링크를 만들지 않고 인증된 운영자 조회로 금액을 확인한다. 구매자 링크가 중지되어도 운영자가 거래를 확인할 수 있다.
- 현재 `/d/` 주소를 운영자의 ‘낙찰자 페이지 보기’가 거부하던 문제를 수정했다. `/d/`, 기존 `/s/`를 허용하고 외부 출처·스크립트 주소는 거부한다.
- 서버 알림 작업자는 실제 발송 직전에 구매자 링크의 현재 세대를 확인한다. 폐기/만료된 주소가 들어 있는 대기 알림은 `expired`와 사유를 기록하고 전송하지 않는다. 일시적인 메타데이터 장애는 전송 없이 재시도한다. 판매 업체 알림에는 이 구매자 링크 판정을 적용하지 않는다.

## API

- `GET /api/platform/channels/:channel/buyer-link-access?itemId=...`: 운영자만 현재 상태·주소·만료·최근 변경 내역 조회. 조회만으로 새 링크를 발급하지 않는다.
- `POST /api/platform/channels/:channel/buyer-link-access`: `itemId`, `action: rotate|revoke|renew`, `expectedRevision`, `requestId`. 같은 경매의 해당 구매자 묶음 전체에 적용한다. 보관 경매는 새 링크·기간 연장으로도 읽기 전용이다.
- `GET /api/platform/channels/:channel/buyer-checkout-preview?itemId=...`: 운영자 인증으로 구매자 결제 표시 데이터 조회. 링크 발급·발송·결제 변경 없음.

## 계정과 보관함 — 로컬 후속 구현

- `buyer-account-auth.js`: OAuth state/브라우저 결합, 앱 ID·사용자 정보·전화번호 확인, HttpOnly 세션, 쓰기 CSRF, 연결 전 15분 이내 로그인 확인. REST 로그인은 PKCE를 적용한다. PKCE 옵션이 없는 Kakao JS 2.8.3 경로는 서버의 REST 키·시크릿으로 교환하며 요청 경로를 저장해 구분한다. 읽기 세션은 7일이다. 카카오 토큰은 저장하지 않는다. 저장되는 상태/세션/계정/낙찰 기록은 AES-GCM으로 암호화하고 저장 키를 AAD로 결합한다.
- `buyer-collection.js`: 로그인만으로 과거 거래를 검색/연결하지 않는다. 검증된 카카오 번호와 일치하는 당시 `winnerPhone`, 현재 유효한 `/d`·`/s` 링크를 함께 확인하고 사용자가 내역 확인 → 연결을 실행한다. 같은 번호의 다른 계정이 이미 연결된 거래를 가져갈 수 없다.
- 과거 회원 명단·닉네임으로 소유권을 추정하지 않는다. 레거시 낙찰에 `winnerPhone`이 없으면 운영자 검토가 필요하다. 지금 번호가 같다는 이유로 다른 경매를 일괄 이관하지 않는다.
- 연결 시 표시용 낙찰번호·업체명·낙찰금·개체 자료를 별도 기록으로 저장한다. 입찰 로그, 전화번호, 계좌와 임의 attributes는 복사하지 않는다. 원장 스냅샷의 기준 시각은 **연결 시각**이다. 연결 전에 이미 덮어쓰거나 삭제한 과거 자료를 복원하는 기능은 아니다.
- 사진 파일은 복제하지 않고 기존 영속 경로만 참조한다. 열람할 때 유효한 접근 주소를 생성한다. 부모는 당시 선택한 ID를 유지하면서 같은 업체의 최신 부모 정보/사진을 조회한다. 이후 개체의 부모 선택을 바꿔도 예전 보관함의 부·모가 다른 개체로 바뀌지 않는다. 부모 원본을 읽을 수 없으면 연결 당시 자료를 표시한다.
- 경매 행 삭제·재사용·재낙찰 이후에도 연결된 기록은 남는다. 새 거래는 별도 `buyerSaleId`/소유권 식별자로 구분한다. 같은 계정이 같은 개체를 다시 연결하면 이전 기록을 덮지 않고 두 기록이 남는다. 변경된 거래는 `거래 변경`, 현재 원장이 없으면 `보관 기록`으로 표시하며 현재 결제 상태로 오인할 데이터를 복사하지 않는다.
- 거래 링크의 단순 만료는 보관함을 막지 않지만 운영자의 새 링크 발급/중지는 기존 보관함 연결도 중지한다. 부모/사진 해석이 끝난 뒤에도 세대를 다시 확인한다. 연결된 기록과 정산 원장을 삭제하지 않는다.
- 같은 요청은 원자적 스냅샷·소유권·계정·요청 영수증 저장으로 한 번만 반영한다. 레거시 개체의 `buyerSaleId`도 같은 쓰기에 포함한다. 계정 목록은 20개씩 표시하고 상세 조회는 연결한 개체 키만 읽는다. 사진이나 전체 과거 경매를 목록 조회 때 가져오지 않는다.
- 새 화면 `/buyer-library.html`: 경매 목록 → 낙찰 개체/사진, 받은 링크로 연결, 로그아웃. 현재 배송·결제 페이지에는 기능이 활성화된 경우에만 보관함 링크를 추가한다. 기존 배송·결제 작업에 로그인을 강제하지 않는다.
- 서버가 재로그인을 요구했을 때 해시만 바꿔 같은 화면에 남던 오류를 수정했다. 실제 로그인 폼으로 이동하고 받은 링크를 유지한다. 깨진 작은 사진은 숨기고 사진 보기에서 재시도할 수 있다.

### 활성화 조건

`.env.example`의 `CREO_BUYER_ACCOUNT_ENABLED=false`가 기본이다. `CREO_BUYER_ACCOUNT_ORIGIN`, `CREO_BUYER_ACCOUNT_SECRET`(32자 이상), `KAKAO_BUYER_CLIENT_ID`, `KAKAO_BUYER_CLIENT_SECRET`, `KAKAO_BUYER_APP_ID`가 모두 유효해야 활성화한다. 실운영 HTTPS에서만 사용하고 리디렉션 URI는 `/api/platform/buyer-account/callback`이다. 현재 실제 값이나 운영 설정은 변경하지 않았다.

같은 앱의 공개 JavaScript 키를 `KAKAO_BUYER_JAVASCRIPT_KEY`에 추가하면 SDK 간편로그인 경로를 준비한다. 값이 없으면 기존 서버 폼으로 로그인한다. 로그인 유지 중인 보관함 방문에서는 SDK를 읽거나 새 로그인 요청을 만들지 않는다. SDK 설정·실제 파일 검증·실패 복귀는 [카카오 간편로그인 연결](KAKAO_BUYER_LOGIN.md)에 정리했다.

아직 운영 활성화하면 안 되는 조건:

1. 실제 카카오 앱/전화번호 동의 권한과 운영 콜백, iOS 카카오 인앱 브라우저 검증 전이다. 카카오 전화번호 제공은 주민 신원 인증이 아니므로 유효한 거래 증거도 요구한다. 비즈니스 채널 등록 자체가 로그인 활성화나 싱크 승인을 의미하지 않는다.
2. 만료 state/세션의 제한된 자동 정리는 구현했다. 만료 후 하루가 지난 암호화 값만 정리하며 삭제 동기화 표시와 SQLite 파일 공간 회수는 별개다. 계정 탈퇴·연결 해제·카카오 해제 통지 처리는 여전히 필요하다.
3. 서명된 브라우저당 10분 20회, 소켓 피어당 600회로 시작 제한을 나눴다. 임의 전달 IP 헤더를 신뢰하지 않는다. 단일 프로세스 메모리 제한이므로 실제 Render 프록시 규모에서 한도 조정과 다중 서버 공통 제한을 검증해야 한다.
4. 잠금은 같은 저장소 객체/프로세스 범위다. 다중 서버의 원자적 소유권 예약/CAS는 별도다.
5. 기존 연결의 새 스냅샷이 없는 경우 다시 연결이 필요하다. 외부 사진 URL 자체의 만료/삭제는 별도이며 Storage 사진 보관 기간도 확정 전이다.
6. `creo_v2::buyer-collection::record::`에 기록된 사진·부모 참조를 보관 대상으로 포함하기 전에는 사진 고아 파일 정리를 실행하면 안 된다. 보관함은 사진 파일을 복제하지 않지만 참조 사진의 삭제를 방지할 운영 정책은 필요하다.

검증과 실제 화면은 [구매자 보관함 감사](ui-audit/BUYER_LIBRARY.md)에 기록한다. 만료 거래 링크의 운영자 기간 연장은 로컬에서 구현·검증했다. 전체 과거 기록 이관과 전체 페이지의 실제 흐름 검토는 계속 남아 있다.

### 로그인 취소·만료 복구와 유지 관리

로그인 취소/시간 만료/공급자·저장 실패 시 앱의 재시도 화면으로 돌아온다. 해당 브라우저에 결합된 거래 링크만 유지한다. 다른 창의 로그인 시작이 이전 창의 결합 쿠키를 덮지 않으며, 이미 로그인한 상태에서 재인증을 취소하면 기존 보관함으로 돌아갈 수 있다. 계정 세션 만료 후에도 저장된 낙찰 기록은 유지한다.

서버 시작 및 1분 주기로 100행 이하를 검사하고 만료 후 하루가 지난 state/세션을 최대 25개씩 정리한다. 현재 값이 달라졌거나 복호화할 수 없으면 보존한다. 작업은 겹치지 않고 서버 종료 시 저장소를 닫기 전에 진행 중 작업을 기다린다. 계정·보관함·정산 원장은 대상이 아니다. 검증은 [로그인 수명 감사](ui-audit/BUYER_AUTH_LIFECYCLE.md)에 기록했다.

2026-09-12 공식 문서 확인: [OIDC 사용자 정보](https://developers.kakao.com/docs/ko/kakaologin/rest-api)는 `phone_number`와 `phone_number_verified`를 제공하지만 전화번호가 있으면 후자는 `true`로 고정이다. 이를 별도의 실명 본인확인으로 설명하지 않는다. [동의항목](https://developers.kakao.com/docs/ko/kakaologin/utilize) 권한·동의가 없거나 카카오가 번호를 보유하지 않으면 번호 제공을 보장할 수 없다. [로그인 설정](https://developers.kakao.com/docs/ko/kakaologin/prerequisite)과 싱크 간편가입 설정은 실제 앱에서 별도로 확인해야 한다.
