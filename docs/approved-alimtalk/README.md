# 승인 알림톡 보관

**2026-09-10 추가 확인·연결:** UL_2129·UL_2136·UL_2138·UL_2139·UL_2144의 승인 원문을 보관하고, **2138·2139·2144를 실행 기본값과 실제 이벤트에 연결**했다. [적용표](APPLICATION_MAP.md)에 연결 위치와 검증 내용을 정리했다. 2129·2136은 예비, UL_2785는 검수중이다. 아래 내용은 기존 6종의 과거 매핑과 테스트 기록이며 새 연결은 적용표가 우선한다.

2026-09-08 사용자가 승인 완료로 제공한 6종을 보관한다. 원문 문구, 변수, 템플릿 코드, 버튼명, 모바일·PC 주소를 각 JSON에 기록했다. `approved-alimtalk.js`가 이 명세를 실행 기본값으로 사용한다. 실제 전송에는 서버의 알리고 인증정보와 발신 프로필 설정이 필요하다.

| 코드 | 용도 | 주소 |
| --- | --- | --- |
| UL_0880 | 첫 낙찰·수령정보 안내 | /d/#{접속코드} |
| UL_0881 | 추가 낙찰 안내 | /d/#{접속코드} |
| UL_0882 | 업체 낙찰 등록 알림 | /w/#{업체접속코드} |
| UL_0883 | 업체 수령정보 등록 알림 | /w/#{업체접속코드} |
| UL_0884 | 별도 낙찰 내역 안내 | /d/#{접속코드} |
| UK_9278 | 구매자 결제 확인 완료 | /s/#{접속코드} |

제공 내용에서 제목은 본문과 분리했다. 중복 표시된 제목과 카카오의 채널추가 설명 문구를 본문에 중복 삽입하지 않았다. 실제 연동 전 알리고에 등록된 본문·강조 제목·버튼 구조와 대조한다. JSON은 보관 명세이며 알리고 API 요청 형식 자체가 아니다.

## 발송 시점 구분

- 수령정보와 결제방식을 한 번에 저장했다면, 실제 수령정보 저장 완료를 기준으로 UL_0883을 보내고 연결 페이지에서 결제방식도 함께 확인하게 한다.
- 운영자 요청에 따라 구매자의 카드결제·입금 완료 신고도 업체에 UL_0883을 재발송한다. 원문은 변경하지 않으며 업체 페이지에서 실제 확인 요청 상태를 보여준다. 이 추가 사용 시점은 템플릿 승인 원문과 별개로 운영자가 선택한 매핑이다.
- UK_9278은 구매자의 입금 신고가 아니라 업체의 결제 확인 완료 시점에 보낸다.
- UL_0880은 첫 낙찰, UL_0884는 카드 링크 등록 후 구매자 재안내에 사용한다. UL_0884 승인 문구와 /d/ 버튼을 그대로 유지하고 연결 페이지에서 카드결제를 제공한다. 추가 사용 시점은 운영자가 선택한 매핑이다.
- 승인 주소 /d/, /w/는 최신 구매자·업체 페이지를 제공하며 /s/, /v/도 호환된다.
- 같은 수령정보·결제방식·개체 구성을 반복 저장하면 알림을 중복 생성하지 않는다. 결제 신고와 업체 최종 확인은 별도 이벤트로 처리한다.
- 모든 자동 결제 알림은 알림톡을 우선 사용한다. 새 이벤트의 `failureSmsFallback: true`는 알리고의 `failover=Y`와 90바이트 이내 `fmessage_1`을 설정한다. 알리고가 실제 전달 실패를 판단해 대체문자를 발송하며, 서버에서 별도 문자를 중복 발송하지 않는다. 설정 누락·API 접수 실패·미열람을 문자 전송으로 간주하지 않는다. `allowSmsFallback: false`로 설정 누락 시에는 대기한다. 기존에 전송된 이벤트는 재발송하지 않는다.

## 실제 알림 타임라인 테스트

테스트 페이지는 기본적으로 자동 발송하지 않는다. 운영자가 실제 발송을 요청한 경우에만 서버 `CREO_CHECKOUT_TEST_DELIVERY_CHANNELS`에 해당 `checkout-test-` 채널 ID를 지정한다(쉼표 구분). 이 채널의 알림 수신자는 업체·구매자 설정에 관계없이 `01049278600`으로 고정한다. 일반 채널의 수신자는 변경하지 않는다. 페이지 상단에서 테스트 알림 활성화 여부를 확인할 수 있다.

수령정보·카드 선택 저장 → 업체 UL_0883 → 업체 카드 링크 등록 → 구매자 UL_0884 → 구매자 결제 신고 → 업체 UL_0883 → 업체 확인 완료 → 구매자 UK_9278 순서로 확인한다. 테스트에서 실제 카드 결제나 입금은 하지 않는다. 같은 버튼을 다시 눌러도 같은 처리를 중복 발송하지 않는다.
