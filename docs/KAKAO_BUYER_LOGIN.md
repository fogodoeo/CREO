# 구매자 카카오 간편로그인 연결

2026-09-12. 사용자 요청은 빠른 카톡 로그인과 장기 낙찰 보관함이다. 기본 거래 링크는 배송·결제로 바로 들어가고, 계정 보관함에서는 연결한 거래를 모아 본다. 실제 운영 활성화와 싱크 신청은 아직 하지 않았다.

## 현재 동작

1. 유효한 계정 세션이 있으면 보관함을 바로 표시한다. 카카오 SDK 다운로드·OAuth 시작을 반복하지 않는다.
2. 로그인이 필요하고 공개 JavaScript 키가 설정되어 있으면 SDK와 일회용 로그인 요청을 준비한다. 사용자 클릭 전에는 카카오 인증을 시작하지 않는다.
3. 버튼 클릭 이벤트에서 `Kakao.Auth.authorize({throughTalk:true,...})`를 바로 호출한다. 클릭 후 네트워크 준비를 기다려 브라우저의 사용자 동작을 잃지 않게 했다. 카톡 없는 환경의 계정 로그인은 SDK가 처리한다.
4. 취소·만료 후 원래 거래 링크를 유지하고 재시도한다. SDK 다운로드/실행 실패 시 `카카오계정으로 로그인` 서버 폼을 제공한다. 서버 준비 실패는 같은 화면의 `다시 시도`로 복구한다.
5. 로그인 화면을 오래 열어둔 경우 표시 중에만 요청을 갱신한다. 앱 전환에서 완료하지 않고 돌아오면 다시 준비한다. 페이지를 떠날 때 요청과 갱신 타이머를 정리한다.

읽기 세션은 7일이고, 새 거래 연결은 15분 이내 로그인 확인을 요구한다. 브라우저 쿠키 삭제/만료 시 재로그인이 필요하다. 기기를 바꿔도 무조건 자동 로그인된다는 뜻은 아니다.

## 카카오톡 채널의 고정 메뉴

사용자는 채널 채팅방의 `내 개체 확인` 메뉴에서 보관함을 열고 싶어 한다. 메뉴는 사용자별 주소 대신 고정된 `/buyer-library.html`에 연결한다. 로그인 세션으로 계정의 보관함을 구분하며 전화번호·낙찰 코드·계정 ID를 메뉴 URL에 넣지 않는다.

설정 위치는 카카오톡 채널 관리자센터 → 비즈니스 도구 → 채팅방 메뉴 → 커스텀 메뉴의 URL 연결이다. [공식 채팅방 메뉴 가이드](https://kakaobusiness.gitbook.io/main/partner/smb/channel/step2/chat2)는 커스텀 메뉴의 웹사이트 연결을 지원한다. 실제 카카오 앱 연결과 운영 배포를 마친 뒤 고정 주소를 메뉴에 등록해야 한다. 현재 채널 메뉴는 수정하지 않았다.

같은 주소를 열어도 로그인된 A 계정에는 A가 연결한 내역, B 계정에는 B가 연결한 내역만 표시한다. 로그인하지 않은 방문자는 카카오 로그인 화면을 본다. 처음 연결하지 않은 계정에는 빈 보관함과 낙찰 링크 연결 동선을 제공한다. 채널 메뉴 클릭 자체를 신원 확인으로 쓰거나 과거 모든 거래를 자동 병합하지 않는다.

## 카카오 설정

실제 카카오디벨로퍼스 앱에서 확인할 항목:

- 카카오 로그인 사용 설정과 OpenID Connect를 켠다.
- JavaScript SDK 도메인에 실제 서비스 출처를 등록한다.
- 리디렉션 URI는 `https://creok.onrender.com/api/platform/buyer-account/callback`이며 서버의 출처 설정과 일치해야 한다.
- 같은 앱의 REST 키, 서버 시크릿, 앱 ID, 공개 JavaScript 키를 연결한다. 브라우저에는 JavaScript 키만 제공하며 서버 비밀과 카카오 토큰은 전달하지 않는다.
- 전화번호 제공 권한·동의항목을 확인한다. 전화번호가 없으면 계정으로 거래를 자동 연결하지 않는다.
- 싱크의 비즈니스 정보 심사·채널 연결·약관 등록 및 간편가입 활성화는 별도로 확인한다. 앱에서 실제로 등록한 약관을 사용하며 코드가 사용자 대신 동의하지 않는다.

`KAKAO_BUYER_JAVASCRIPT_KEY`는 선택 설정이다. 전체 계정 기능은 여전히 기본 비활성 상태다. 실제 값을 추가하거나 운영 재시작/배포를 하지 않았다.

## SDK와 인증 경계

공식 **2.8.3** SDK를 고정하고 공식 다운로드 페이지의 SHA-384 SRI와 받은 파일 해시를 대조했다. `public/buyer-kakao-login.js`는 로그인 화면에서만 필요한 시점에 SDK를 읽는다. SDK는 `init()` 전에는 `Auth` 네임스페이스가 없으므로 초기화 전·후 검사를 구분한다.

확인한 SDK 2.8.3의 공개 옵션에는 PKCE가 없다. SDK 경로의 `/prepare`는 서버에 `transport:talk` state를 저장하고, 공식 방식대로 REST 키와 시크릿으로 토큰을 교환한다. 기존 `/start` REST 경로는 별도의 PKCE verifier를 유지한다. 브라우저 입력으로 콜백·동의 범위·서버 교환 경로를 바꾸지 못한다. 두 경로 모두 같은 브라우저 결합, 일회용 state, 시작 제한, 앱 ID와 사용자 정보 확인을 거친다.

공식 근거: [JavaScript 로그인](https://developers.kakao.com/docs/ko/kakaologin/js), [SDK 레퍼런스](https://developers.kakao.com/sdk/reference/js/release/Kakao.Auth.html), [SDK 다운로드](https://developers.kakao.com/docs/ko/javascript/download), [앱/싱크 설정](https://developers.kakao.com/docs/ko/kakaologin/prerequisite).

## 검증과 남은 범위

위험도 **release**. 임시 SQLite와 가짜 구매자/카카오 토큰 공급자를 사용했다.

- `node --test test/buyer-auth-lifecycle.test.js`: **11개 통과**. 새 4개 시나리오는 공개 응답/서버 비밀 분리, REST·SDK 혼합과 재시작/중복/PKCE 유지, Origin·브라우저·만료·공유 시작 제한, 설정 누락·다른 앱·저장 실패를 확인한다.
- `npm run check`, 서버 전체 `npm test` **618개**, PC `python -m unittest discover -p "test*.py"` **189개** 통과.
- PC `node scratch/checkout-redesign/buyer-kakao-sdk-check.cjs`: 실제 고정 SDK 파일을 로드하고 로그인 URL 이동을 로컬 공급자로 전환했다. 초기화 전 Auth 검사 오류를 실제 SDK에서 발견해 수정했다. 클릭 시 사용자 동작 활성 상태·추가 fetch 없음, 원래 거래 연결, 세션 유지 시 SDK 생략, 취소/차단/예외/저장 오류/오래된 요청 갱신, 앱 복귀 이벤트를 검사했다. 320/390/800px, 200% CSS 확대, 키보드 포커스/44px 이상 버튼 통과. 준비 화면과 차단 복구 캡처를 직접 확인했다.
- 인접 `buyer-auth-recovery-check.cjs`, `buyer-library-check.cjs`, `buyer-navigation-check.cjs` 통과. 기존 계정 폼 복구·소유권 연결·배송 흐름이 유지된다.
- 같은 고정 보관함 URL에 두 가상 카카오 계정으로 진입했다. A의 연결된 거래는 재방문 즉시 표시되고 B의 목록은 비어 있으며, B가 A의 상세 ID로 조회해도 404를 반환한다. 실제 SDK 검사에 이 메뉴 진입 회귀를 포함했다.

테스트 초기의 native 서버 폼 리디렉션이 도구의 요청 가로채기를 우회해 공개 카카오 로그인 페이지로 이동했다. 가짜 앱 키였고 계정 로그인/고객 정보 입력은 하지 않았다. 이후 native 응답을 `maxRedirects:0`에서 로컬 콜백으로 바꾸고 브라우저 외부 DNS도 차단했다. 최종 검증의 예상 밖 외부 요청은 0건이다. 공개 SDK 파일 다운로드는 별도이며 실제 인증 테스트를 의미하지 않는다.

실제 카카오 앱 권한·동의·시크릿, Android/iOS 카톡 앱 전환과 Safari, 싱크 약관/탈퇴 동선은 미검증이다. 자동 로그인 프롬프트나 싱크 승인을 완료했다고 표시하지 않는다. 계정 해제 통지·탈퇴/보존 정책·과거 낙찰 이관과 전체 페이지 감사는 계속 남아 있다. 운영 배포/고객 기록 변경/알림 발송은 없다.
