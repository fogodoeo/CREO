# 2026-09-12 거래 페이지와 운영 진입 배포

사용자 요청: 로컬 개선을 정리해 운영에 반영하고, 공개 홈은 안내 화면으로 두며 `/main`은 별도 비밀번호로 보호한다.

## 포함 범위

- 구매자 내 개체/배송·결제 구분, 수령·결제 선택과 확인 상태, 사진·부모 정보·업체 문의.
- 업체 출품/낙찰·정산/업체 정보 메뉴, 피들 가져오기, 부모 재사용, 연락처 간소화 및 선택형 개인 1:1 오픈채팅.
- 운영자 출품 검토와 편성, 구매자 링크 연장/교체/철회, 사진 사용량 조회.
- 주관사 조회 실패 복구, 권한 만료 화면 정리, 부분·초과 입금 표시. 기존 입금 기록 방식을 유지한다.
- 낙찰·결제 변경과 알림의 원자적 저장, 중복·응답 유실 재시도 보호.
- 공개 `/`, 보호된 `/main`, 기존 `/index.html` 별칭. PC/API 키와 고객 링크 서명 키는 교체하지 않는다.

카카오 계정 로그인/장기 보관함 코드도 포함하지만 실제 카카오 설정 전에는 비활성 상태다. 과거 고객 전체 이관·사진 자동 삭제·새 gateway 서비스는 수행하지 않는다. 로컬 전용 HTML, 개인 환경 파일, 별도 Dodosi 작업은 제외한다.

## 배포 전 확인

- 위험도 release. `npm run check`, 작업 폴더 서버 전체 649개, PC 189개 통과.
- 스테이징한 배포 파일만 별도 디렉터리로 내보내 **운영과 같은 Node 22.23.2**에서 전체 635개 통과. 미배포 Dodosi 테스트 14개는 이 묶음에 없다.
- 실제 로컬 Chrome의 구매자·업체·주관사·운영 로그인 확인은 역할별 검토 문서에 기록했다. 최근 운영 로그인 3그룹, 주관사 복구 6그룹 통과.
- UTF-8 엄격 디코딩, 대체 문자·비밀번호 해시 혼입·누락된 로컬 require, `git diff --cached --check` 통과.
- 기존 배포는 `61810bd`. 운영 조회 결과 크드컵 30/30 종료, 기타 공개 경매도 입찰 진행 모드는 없었다. 경매 상태·낙찰·고객 자료는 변경하지 않았다.
- Render의 `CREO_OPERATOR_PASSWORD_HASH`를 Save only로 먼저 등록했다.
- 기존 Supabase 프로젝트에 `auction-entry-photos` 비공개 버킷을 준비했다. 조회 200, public=false, 파일 400,000바이트 제한, WebP만 허용. 기존 버킷/파일은 수정하지 않았다.
- 배포 전 서버 정상, SQLite durable=true, 미러 outboxPending=0. 기존 mirrorError에 과거 504가 남아 있었으며 BAND 가입관리 작업은 LOGIN_REQUIRED였다. 이번 UI/메인 변경과 별개인 기존 상태다.

## 운영 검증 / 남은 범위

코드 배포 후 실제 커밋, `/`·익명/인증 `/main`, 기존 개인 링크 경로, 새 정적 파일, 서버 상태를 읽기 전용으로 확인한다. 실제 Linux 코덱과 Supabase 업로드/서명 조회는 가상 테스트 이미지로 확인하고 해당 파일만 정리한다. 고객 자료와 실제 알림 발송은 테스트에 사용하지 않는다.

배포 후 관찰 결과는 이 문서에 추가한다. 전체 페이지 감사, 실제 카카오 앱 로그인과 모바일 앱 전환, 장기 보관·탈퇴 정책은 별도 후속 범위다.
