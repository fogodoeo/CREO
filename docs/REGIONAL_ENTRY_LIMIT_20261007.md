# 권역별 참여업체 수에 따른 개체 등록 한도

## 정책

- 전국크레자랑의 모든 권역에 적용한다. 활성 참여업체가 8곳 이하면 기존 4~5개체, 9곳 이상이면 업체당 최대 4개체다.
- 예약 업체 수가 아니라 해당 권역에 등록된 활성 업체 수를 센다. 대표 접속 전 사전등록 업체도 포함한다. 사용 중지·삭제 업체는 제외하고 업체 ID로 중복을 제거한다. 같은 대표 번호를 사용하는 서로 다른 업체는 각각 센다.
- 운영자가 지정한 방송 권역을 우선한다. 업체의 실제 배송 출발지와 방송 권역은 별개다.
- 조회 및 저장 시 최신 업체 목록으로 계산한다. 예약·개별 저장·일괄 제출을 서버에서도 검증한다. 오래 열린 화면의 5번째 개체 제출도 거부한다.
- 기존 5칸 예약과 개체 자료는 삭제하지 않는다. 현재 허용된 4칸만 편집하고, 남은 작성 자료는 펼쳐서 확인한다. 이미 제출한 초과 개체는 완료로 간주하지 않으며 제출 철회 또는 운영자 검토가 필요하다. 승인된 경매 개체를 자동 삭제하지 않는다.
- 과거 방송은 원래 예약 한도로 조회한다. 기존 예약의 quantity는 확보한 최대 자리 수를 보존하며, 현재 등록 한도는 entryLimit이다. 참여업체가 줄면 기존 5칸 예약은 다시 5칸을 사용할 수 있지만 4칸으로 생성한 예약을 자동 확장하지 않는다.

## 화면 원칙

- 기존 공통 서체·간격·색상과 입력 컴포넌트를 유지한다. 새 장식이나 애니메이션 없이 입력표 위에 권역 업체 수와 한도를 한 줄로 표시한다.
- 보관된 초과 자료는 접힌 details로 구분하여 4개 입력 흐름을 방해하지 않는다. 제출 철회는 명시적인 버튼이며 자동 실행하지 않는다.
- 운영자 회차에는 권역 전체 업체 수/개체 한도와 해당 회차 신청 업체 수를 각각 표시한다.

## 도도시 배송 일정 표시

- 2026-10-07 도도시 공식 서울A → 대구 상세 페이지의 이미지 시간표를 확인했다: 화요일 출발 → 수요일 대구 도착, 토요일 출발 → 일요일 대구 도착. 출처: https://www.dodosi.co.kr/shop_view?idx=873
- 기존 계산은 일요일 도착편을 월요일 방송에 이미 포함하고 있었다. 달력 칸 위쪽 2px 구간선으로 접수/맡기기부터 도착까지 연결한다. 파르게는 회색 점선, 도도시는 파란 실선으로 구별하고 선 시작에 배송사 이름을 직접 표시한다. 주 경계와 달 경계에서도 이름과 구간을 이어 표시한다.
- 날짜를 누르면 맡기기 → 출발 → 대구 도착 상세 날짜를 연다. 세 단계 표는 상세 창 안에만 두어 기본 화면 높이를 늘리지 않는다. 방송과 겹치는 날에는 상세 창의 '이날 방송 보기'로 접근할 수 있다. 임의로 출발일을 맡기는 마감일로 변경하지 않는다.
- 방송 당일 도착은 도도시만 허용하는 기존 정책을 유지한다. 당일편에는 도착 시각 확인 문구를 표시한다. 노선 전체를 새로 조사하거나 외부 운송 예약을 실행한 것은 아니다.

## 검증

- 위험도 Release: 예약 한도와 인증된 웹 API 조회 변경. PC 경매 프로토콜·낙찰·결제·승인 로직은 변경하지 않았다.
- 집중 등록/업체 생명주기 38개, 배송 화면 렌더러 7개 통과. 구간 중간 날짜 클릭과 월 경계 표시를 추가 검증했다.
- npm run check 통과, npm test 1,017개 전부 통과. 이후 배송사 이름을 선에 표시하는 마크업·스타일 수정은 집중 7개와 실제 390px 모바일 렌더링으로 재확인했다.
- 5개 권역의 8/9 경계, 중복 ID, 비활성 제외, 사전등록 포함, 권역 변경, 다른 권역 격리, 동시 요청/중복 재시도, 재시작, 기존 5번째 자료 보존, 오래된 일괄 제출의 전체 거부, 초과 제출 철회를 검증했다. 기존 실패 롤백·마감·권한 테스트도 통과했다.
- 격리된 실제 브라우저에서 기존 5칸 예약이 4개 입력행으로 표시되고, 4개체 제출 후 완료/배송 안내가 표시됨을 확인했다. 도도시 모바일 390px 화면에서 금요일 맡기기/토요일 출발/일요일 도착을 확인했다. 실물 모바일 키보드는 미검증이다.
- 별도 PC 저장소를 찾지 못해 PC 테스트는 실행하지 않았다. 운영 테스트 자료와 실제 알림은 만들지 않았다.
- 화면 증빙은 사용자 작업 폴더 output/regional-entry-limit에 보관한다. 운영 반영 확인은 배포 후 읽기 전용으로 진행한다.
