# 개체·부모 사진 표시안

상태: 기존 사진 필드 조회, 출품/부모 영속 저장, 최신 부모 조회, 인증된 사진 업로드 HTTP 경로를 구매자·업체 공통 뷰어와 연결했다. 임시 SQLite+비공개 로컬 파일로 업로드/재시작/사진 열람을 검증했다. 업체 작성 화면의 HTTP 연동·실제 Supabase 계정 업로드·운영 배포는 미완료다. 상세와 제한은 [사진 저장 구현 기록](ENTRY_PHOTO_STORAGE.md)을 따른다.

## 화면

- 구매자 낙찰 내역과 업체 구매자별 개체 내역에서 같은 사진 구성 요소를 사용한다.
- 사진이 있으면 개체 이름 옆의 작은 미리보기와 `사진 보기`로 진입한다. 눌렀을 때 큰 사진과 `개체 / 부 / 모` 선택지를 제공한다. 실제 사진이 있는 선택지만 표시한다.
- 사진이 하나도 없으면 텍스트 내역 그대로 유지한다. 빈 사진 틀, 카메라 아이콘, `사진 없음` 문구, 빈 부모 칸을 만들지 않는다.
- 실제 개체 확인을 위한 큰 사진은 자르지 않고 전체 비율을 보존한다. 이름·번호·해당 사진의 관계를 함께 보여준다.
- 개체의 제출·확정 정보는 해당 개체 자료로 보관한다. 부모 프로필은 업체가 수정한 최신 이름·모프·사진을 연결된 개체/구매자 화면에 반영한다(사용자 확정). 변경 전 부모 버전은 이력으로 남긴다.

## 저장·전송 제안

- 업로드 시 미리보기(예: 320px, 20–40KB)와 큰 보기(예: 긴 변 1600px, 150–350KB 목표)를 한 번 생성한다. 실제 화질과 크기는 샘플을 보고 조정한다.
- 이미지 파일은 Storage에, 식별자·경로·가로세로·파일 크기만 DB에 저장한다. Base64 사진을 낙찰 목록 응답에 포함하지 않는다.
- 작은 사진만 필요할 때 읽고, 큰 사진은 눌렀을 때 요청한다. 변경하지 않는 파일은 동일한 URL과 캐시 정책을 유지한다.
- 같은 부모 사진은 하나의 파일을 여러 개체에서 참조한다. 개체마다 재업로드하지 않는다.
- Supabase 실시간 Image Transformations 대신 미리 생성한 파일을 제공하면 별도의 변환 과금을 피할 수 있다.
- 새 출품 사진은 비공개로 구현했다. 개인 링크 권한 확인 후 이미지 접근 주소를 발급하고, 사진 요청에서 Storage 서명 URL로 이동한다. 이미지 바이트를 Render로 중계하지 않는다. 원격 설정이 없을 때 임시 디스크로 대체 저장하지 않는다.

## 현재 코드 확인

- `public/supabase-bridge.js`의 `uploadPhotos`: `auction-photos` Storage 업로드 후 공개 URL을 반환한다. 실패 시 WebP data URL을 반환해 DB 사진 필드에 넣는 대체 경로가 남아 있다. 향후 사진 기능에서는 별도로 정리해야 한다.
- 같은 파일의 개체 조회에는 개체·부·모 사진 필드 및 부모 ID 참조가 있다. 새 거래 응답은 기존 사진을 공통 모델로 연결하고, 새 출품의 부모 ID는 공통 업체 부모 저장소에서 최신 자료를 읽는다. 변경 이전 부모 기록과 승인 스냅샷은 보존한다. 부모 저장소 조회 실패 시 승인 당시 자료로 표시해 결제 조회를 계속 제공한다.
- `capture-api.js`의 캡처 조회는 Storage에서 이미지를 읽어 Render 응답으로 전달한다. 캡처를 거래 사진에 그대로 연결하면 저장소 전송뿐 아니라 Render 경유도 고려해야 한다.
- 실제 운영 요금제·청구 기간 사용량·현재 사진의 평균 크기는 이번에 조회하지 않았다.
- 운영자 검토 창도 같은 뷰어를 사용하며 누른 개체/부모 사진부터 연다. 사진 없이 등록한 부모는 이름·모프만 표시한다. `A01 · A01`처럼 같은 식별번호가 중복되던 표시도 제거했다.

### 사용자 운영량 반영

사용자가 Free 플랜과 주당 약 80마리 낙찰을 확인했다. 현재 청구 기간의 실제 사용량은 아직 조회하지 않았다.

월평균 약 347마리(80 × 52 ÷ 12), 사진별 큰 보기 200KB + 썸네일 30KB, 압축 전 원본은 별도로 저장하지 않는다고 가정한다.

| 마리당 사진 | 월 저장 증가 | 모든 사진을 마리당 총 10회 새로 내려받을 때 |
| --- | --- | --- |
| 3장: 개체 1 + 부 1 + 모 1 | 약 239MB | 약 2.39GB/월 |
| 5장: 개체 3 + 부 1 + 모 1 | 약 399MB | 약 3.99GB/월 |

구매자·업체 열람을 합산한 계산이며 매번 새로 다운로드하는 보수적인 가정이다. 무료 저장소가 비어 있다고 해도 3장 구성은 약 4개월, 5장 구성은 약 2.5개월에 1GB 근처에 도달한다. 현재 저장 파일과 다른 트래픽, 더 큰 사진, 미낙찰·미승인·초안 출품은 별도다. 같은 부모 사진 재사용과 브라우저 캐시는 실제 사용량을 줄인다. Free의 일반/캐시 전송 각각 5GB는 서로 독립적인 한도이므로 무조건 합산 10GB로 판단하지 않는다. 임의 자동 삭제는 하지 않는다.

## 비용 예시

2026-09-12 조회한 공식 요금: Free 저장 1GB, 일반/캐시 전송 각각 5GB. Pro 월 $25부터, 저장 100GB, 일반/캐시 전송 각각 250GB 포함. 포함량 초과 시 저장 $0.0213/GB·월, 캐시 전송 $0.03/GB, 일반 전송 $0.09/GB. 두 전송 한도는 독립적이다.

사진 3장 × 장당 200KB를 매번 새로 받는다고 가정한 십진 단위 계산:

| 세 장을 모두 내려받은 횟수 | 큰 사진 전송량 |
| --- | --- |
| 1,000회 | 약 0.6GB |
| 10,000회 | 약 6GB |
| 100,000회 | 약 60GB |

작은 미리보기와 다른 서비스 트래픽은 별도다. 브라우저 캐시에 남은 사진의 재사용은 실제 다운로드를 줄인다. CDN 캐시에서 내려받는 전송은 무료 다운로드가 아니라 캐시 전송량에 해당한다. 전송 한도가 이미 소진된 유료 플랜에서 추가 6GB 전송료는 캐시 적중 정도에 따라 약 $0.18–$0.54다. 무료 플랜 초과를 이 유료 단가로 계산하면 안 된다.

개체 1,000마리에 각각 사진 3장, 200KB 큰 보기 + 30KB 미리보기라면 약 690MB 저장이다. 고해상도 원본을 보관하면 그 용량이 별도로 더해진다.
