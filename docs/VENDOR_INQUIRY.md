# 개체별 업체 문의 — 로컬 검토

구매자 낙찰 내역·내 개체·개인 보관함에서 `업체 문의`를 연다. 업체명과 개체번호를 먼저 보여주고 등록된 카카오톡 채널·전화만 제공한다. 경매명·업체명·개체번호가 들어간 문의 문구는 접어서 두고 필요할 때 복사한다. 버튼 열기·복사는 저장이나 알림 발송을 만들지 않는다.

## 업체 등록

기본 등록은 **업체 연락처 하나**다. `문의 담당자 따로 설정`을 켰을 때만 직원 번호를 입력한다. 카카오톡 상담은 별도 접힘 항목으로 둔다. 전화번호 복사 버튼과 두 개의 큰 연락처 섹션을 제거했다.

| 설정 | 사용처 | 구매자 공개 |
| --- | --- | --- |
| 업체 연락처 (`phone`) | 운영자 목록·낙찰·수령정보·결제 확인 업무 알림 | 기본 번호를 함께 쓰기로 선택한 경우 |
| 고객 문의 전화 (`inquiryPhone`) | 개체 문의·결제 화면 문의·다른 참여업체 연락처 | 등록한 경우 |
| 카카오톡 상담 링크 (`kakaoUrl`) | 업체 채널 또는 개인 1:1 오픈채팅 연결 | 등록한 경우 |

`inquiryPhoneMode=shared`이면 업체 연락처를 바꿀 때 문의 번호도 함께 바뀐다. `separate`이면 직원 문의 번호를 독립적으로 유지한다. 별도 문의 번호를 비워두면 전화 문의를 표시하지 않는다. 기존 별도/비공개 문의 설정은 자동으로 공개하지 않는다. 새 운영자 등록 업체는 공개 전화가 빈 상태이며, 업체 화면에서 기본 번호 공유를 선택해 저장할 수 있다. 담당자/계좌 등 추가 개인정보를 문의 응답에 넣지 않는다.

- `업체 정보 → 업체 연락처`에서 등록한다. 최초 팝업과 업체 페이지가 같은 연락처 컴포넌트를 사용하며, 최초 팝업에서는 카톡 주소 입력을 생략한다. 운영자 목록은 기본 번호 하나를 표시한다.
- 옛 클라이언트가 문의 설정을 보내지 않으면 기존 방식을 유지한다. 명시적으로 문의 번호를 보내는 옛 클라이언트는 별도 번호 저장으로 해석한다. 빈 값은 공개 취소이며 기본 번호로 대체하지 않는다.
- 공통 업체 프로필의 연결된 경매에 공유하고 기존 revision 충돌 검사를 따른다.
- 업체 채널은 `https://pf.kakao.com/_채널ID` 또는 `/chat`을 받아 채팅 주소로 정규화한다. 개인 1:1 오픈채팅은 `https://open.kakao.com/o/s…`, 오픈프로필은 `https://open.kakao.com/me/…` 형식을 받는다. 일반 그룹 링크(`/o/g…`), 외부 도메인·자격증명·쿼리·스크립트 주소는 거절한다.
- 실제 문의에는 업체 채널의 1:1 채팅 설정도 필요하다. 카카오 공식 [채팅 안내](https://kakaobusiness.gitbook.io/main/channel/run/chat), [채널 버튼 안내](https://developers.kakao.com/docs/ko/kakaotalk-channel/js)를 참고했다. 문구 자동 입력·전송은 구현하지 않았으며 `문구 복사` 후 구매자가 보낸다.
- 카카오톡에서 페이지를 열거나 로그인하는 것만으로 개인 상담 주소를 자동 등록하지 않는다. 공식 채널 채팅 API는 `channelPublicId`를 별도로 요구한다. 개인 카카오톡 사용자는 1:1 오픈채팅/오픈프로필 링크를 등록할 수 있다. 카카오 [오픈채팅 공식 소개](https://www.kakaocorp.com/page/service/service/openchat)는 오픈프로필 링크를 통한 친구 추가 없는 1:1 대화를 안내한다. 이는 일반 개인 카톡 ID/전화번호로 채팅방을 자동 생성하는 기능이 아니다.

## 거래·보관함 연결

- 거래 페이지는 해당 개체의 정확한 업체 ID로만 문의처를 찾는다. 같은 이름의 다른 업체로 대체하지 않는다.
- 보관함 연결 시 원래 공통 업체 프로필 ID를 암호화된 기록에 저장한다. 현재 경매의 개체 행이 재사용되거나 삭제되어도 문의처를 다른 판매업체로 바꾸지 않는다.
- 문의처는 원래 업체 프로필의 최신 정보를 조회한다. 은행·운영자 메모·내부 프로필 ID를 구매자 응답에 포함하지 않는다.
- 원래 프로필 식별자가 없는 과거 보관 기록은 임의 추정하지 않는다. 연락처·유효한 원래 프로필이 없으면 문의 버튼을 표시하지 않는다. 기존 기록을 일괄 재연결하는 작업은 별도다.
- 로그인 및 거래 링크 접근·폐기 검증은 기존 규칙을 유지한다.

## 검증

### 개인 카톡 문의 확장 — 2026-09-12

- 입력 이름을 `문의받을 카카오톡 링크`로 바꾸고 `개인 1:1 오픈채팅 또는 업체 채널`만 안내한다. 업무 알림 번호는 변경하지 않는다.
- 위 링크 형식 검증, 그룹 링크 거부, 실제 API 저장·재시작·구매자 버튼 연결·등록 제거 경로를 검증했다. 링크 대상의 실제 소유권, 1:1 수신 허용 상태와 모바일 카톡 앱 전환은 실제 담당자 링크가 없어 미검증이다. 코드 형식 검사를 링크의 실제 유효성 검증이라고 부르지 않는다.
- 집중 `vendor-inquiry / checkout-preferences / vendor-directory / buyer-account` **46개**, `npm run check`, 서버 전체 **635개**, PC **189개** 통과. 실제 브라우저 `buyer-inquiry-check.cjs` **6그룹** 통과. 설정 화면을 이미지로 검토했다. 가상 링크를 외부로 열거나 메시지를 보내지 않았다.
