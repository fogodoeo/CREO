# 전국크레자랑 회원 수집·자동승인

대상은 BAND `104432443`이며, 전용 공동리더 계정으로 실행한다.

## 서비스 구성

- 운영 서버: `creok` / 회원 화면 `/band-members.html`
- 분리된 무료 워커: `creo-band-approvals` / `band-approval-worker` 브랜치
- 워커 시작 명령: `python3 band_directory_bot.py`
- 영구 DB: 운영 서버의 `CREO_DATA_DIR/band-members.sqlite`
- 운영 서버가 워커 `/healthz`를 5분마다 호출한다. 사용자의 PC나 열린 웹페이지는 필요 없다.

신청 목록은 약 3초 간격으로 확인한다. 처음에는 기존 회원 명단을 모은 뒤 10명씩 상세 프로필과 가입답변을 저장한다. 동시에 실행하는 상세 조회는 최대 3개다. 현재 BAND의 명단 응답은 1,001명으로 제한될 수 있으므로, 화면에서 지원하는 정렬 결과를 합치고 BAND의 전체 회원 수와 일치하는지 검증한다. 수집 완료 후에는 10분 간격으로 프로필 변경과 최근 가입자를 확인한다.

## 승인 및 낙찰 연락처

회원은 이름 대신 BAND의 원래 `member_key`로 구분한다. Base64 패딩을 포함한 식별자를 변형하지 않는다. 기존 회원과 신규 신청은 같은 DB에 저장한다.

연락처 우선순위는 프로필 → 가입답변 → 관리 화면에 실제 공개된 인증 휴대폰번호다. 프로필 형식이나 업체 이름은 거절 사유가 아니다. 프로필에 번호가 없어도 가입답변에서 유효한 번호를 찾으면 승인할 수 있다. 모든 출처에서 번호를 확인할 수 없으면 신청을 대기로 남기며 자동 반려하지 않는다.

인증 배지만으로 번호를 만들지 않는다. 가입 이력의 마스킹된 번호나 일회용 인증코드도 연락처로 사용하지 않는다. 과거 가입답변이 BAND에서 제공되지 않으면 기존에 저장한 답변을 지우지 않는다.

승인 전에 회원과 처리 기록을 영구 저장한다. 승인 응답이 유실되면 같은 요청을 자동 재전송하지 않는다. 처리 상태가 불확실한 건은 BAND의 실제 회원 상태를 확인해야 한다. 낙찰 안내는 번호 선택을 끝낸 뒤 생성하며, 발송 응답이 불확실하다고 다른 번호로 재발송하지 않는다.

## 로그인과 장애 복구

최초 쿠키는 워커의 비공개 `BAND_COOKIE_JSON`, 브라우저 사용자 에이전트는 `BAND_CHROME_USER_AGENT`, 세션 세대는 `BAND_SESSION_REVISION`에 설정한다. 비밀 값은 Git, 로그, 문서에 기록하지 않는다.

워커는 BAND 인증 확인 직후 최신 쿠키를 운영 서버의 AES-GCM 암호화 저장소에 보관한다. 30초마다 변경 여부를 확인하되 바뀌었을 때만 저장한다. 재시작하면 같은 세대의 최신 저장본을 먼저 사용한다. DB가 일시적으로 응답하지 않으면 이전 쿠키로 접속하지 않고 건강 확인 응답을 유지하며 재시도한다.

`login_required`이면 전용 공동리더 계정의 재로그인이 필요하다. 새 쿠키와 새 `BAND_SESSION_REVISION`을 함께 설정하고 재배포한다. 세션 저장 승인을 받았더라도 인증코드 입력이나 로그인 자체는 계정 소유자가 완료한다.

`BAND_DIRECTORY_AUTO_APPROVE=false`로 승인만 중지할 수 있다. 설정 변경 후 워커를 재배포해야 적용된다. 수집 위치는 DB에 남으므로 재배포 후 이어서 처리한다. 워커 브랜치는 수동 배포하며, Render 배포 요청에 정확한 `commitId`를 지정한다.

## 운영 확인

- 회원 화면에서 전체 수, 연락처 수, 봇 연결과 수집 완료 상태를 확인한다.
- `/api/band-directory/*`의 회원·상태 조회는 운영자 인증이 필요하다.
- `/api/band-directory/bot/*`는 이 기능에만 쓰는 비공개 토큰으로 접근한다.
- 공개 건강 확인 응답에는 휴대폰번호, 가입답변, 쿠키를 포함하지 않는다.
- 실제 고객에게 시험 카톡을 보내지 말고 테스트 데이터로 연락처 선택을 검증한다.
