# 송출 비고 · 출품 번호 · 주관사 낙찰 내역

로컬 검토 및 운영 배포 준비 완료. 2026-09-17 사용자가 비고 표시 스위치 추가 후 운영 배포를 요청했다. 운영 경매 데이터 변경은 포함하지 않는다.

## 범위

- HTML/CSS/일반 JavaScript, 기존 `CHECKOUT_DESIGN.md`와 `BROADCAST_DESIGN_BASE.md` 적용.
- `better-interface`의 접근성·레이아웃·문구·타이포그래피·색상·UI 기준, 비고 이동에는 `emil-design-eng` 참고.
- 위험도 **release**: 화면 표현, 출품 검토의 번호 제안, 인증된 주관사 읽기 응답 및 저장되는 송출 설정 추가 후 운영 배포. 기존 출품 승인 검증·낙찰 처리·입금 기록 로직은 유지.
- P2 배치 → 문구·표시 설정 → 비고 표시. 기본값은 기존 노출을 유지하는 켜짐이며, 끄고 `변경 저장`하면 비고 행과 공간만 숨긴다. 출품 원본은 보존하며 채널별로 저장한다.
- 기존 크드컵처럼 팀 그룹이 설정된 경매는 번호를 부 번호로 추정하지 않고 직접 입력으로 시작한다.
- 번호는 식별자, 진행 순서는 별도다. A/B 선택이 이미 편성된 개체를 재번호 부여하거나 재정렬하지 않는다. 빈 번호 제안 후에도 서버의 번호·진행 순서 중복 검증을 통과해야 편성된다.

## 검증

가상의 업체·낙찰자를 임시 SQLite에 구성했다. 알림 발송 공급자는 연결하지 않았다.

통과:

- 집중 테스트: `node --test test/entry-numbering.test.js test/broadcast-item-notes.test.js test/organizer-auction.test.js test/organizer-recovery-ui.test.js test/organizer-receipts.test.js` — 최초 24개 통과. 이후 화면 높이/픽셀 폭 회귀 테스트 1개를 추가하여 전체 실행에 포함.
- 전체 서버: `node --test --test-concurrency=2` — **717/717 통과**, 실패·건너뜀 0. 최초 릴리스 검사에서 새 설정 추가에 따른 이전 기본값/함수 인자 정적 검증 2개가 실패하여 기대값을 갱신한 후 전체 재실행했다.
- 모니터링 앱: `python -m unittest discover -p "test*.py"` — **192/192 통과**. 프린터·발송은 테스트 대역으로 검증하고 실물 인쇄나 실제 발송은 하지 않았다.
- 비고 설정 집중 검증: 반복·동시 저장, 다른 채널 분리, 미인증 거부, 부분 저장, 서버 재생성 후 유지, 원본 개체·입찰·진행 상태 보존, 꺼짐/켜짐의 두 렌더링 형태.
- `npm run check` 통과. 변경/추가 파일 22개 UTF-8 검사 및 JavaScript/HTML 인라인 script 22개 추가 구문 검사 통과.
- `git diff --check` 통과. UTF-8 교체 문자 및 의도하지 않은 대량 변경 없음.
- 실화면: 주관사 390px 목록, 320px 긴 업체명·수령지 펼침, 검색 결과, 정산 화면 복귀, 남은 금액/오늘 날짜가 채워진 기존 입금 팝업.
- 실화면: 출품 A04 제안 → 2부 B04 선택 → 가짜 개체 편성 → 다음 출품 B05/진행 순서 8 제안.
- 실화면: 기본·픽셀 P2의 긴 비고, 비고 미등록 시 행 제거, 대기 상태에서 이전 개체/비고 모두 제거. 레거시 `direct=1` 경로에서도 별도 행 확인.

- 세 화면에서 검증 중 JavaScript 오류·경고 없음.

미검증/경계:

- 운영 서버 배포 및 방송 프로그램의 실제 카메라 합성은 수행하지 않음.
- reduced-motion은 CSS와 회귀 검사로 확인했고 실제 OS 설정 전환은 수행하지 않음.
- A/B 번호 선택은 기존 진행 순서를 자동 재배치하지 않음. 편성 시 진행 순서를 별도로 확인한다.
- 연락처가 아예 남아 있지 않은 과거 배송 기록의 낙찰자 동일성은 확정할 수 없다. 양쪽 전화번호가 있는 경우 불일치 기록은 표시하지 않는다.
