# 옹동2 전체 경험 개선 — 진행 기록

상태: 진행 중. 운영 배포 전 로컬 검토 원칙을 유지한다. 이 문서의 일부 완료가 전체 목표 완료를 뜻하지 않는다.

최근 추가: 개체별 업체 문의를 구매자 거래 화면과 장기 보관함에 연결했다. 업체 연락처 하나로 업무 알림·전화 문의를 받는 기본 화면으로 간소화하고, 직원 문의 번호는 선택 시에만 펼친다. 카카오톡 상담도 선택 항목으로 접어둔다. 기존 별도/비공개 문의 설정은 유지하고, 원래 판매업체의 공통 프로필을 기준으로 문의처를 조회한다. 로컬 검증은 서버 634개·PC 189개와 실제 모바일 브라우저 5그룹을 통과했다. 세부 범위·이전 기록의 제한·검증은 [VENDOR_INQUIRY.md](VENDOR_INQUIRY.md)에 기록했다. 운영에는 아직 배포하지 않았다.

후속 진행: 만료 링크의 `기간 연장`과 주소 교체를 분리해 단순 만료 복구에서 기존 보관함을 유지한다. 구매자 오류 화면에서도 보관함으로 이동할 수 있다. 서버 632개·PC 189개 및 실제 운영자/구매자 브라우저 경로를 통과했다. [LINK_RENEWAL.md](ui-audit/LINK_RENEWAL.md)에 검증을 기록했다. 전체 과거 이관과 전체 페이지 검토·실제 계정/운영 환경 검증은 아직 남아 있다.

## 확정한 방향

- 페이지 목적별 밀도는 다르게 한다. 거래용 모바일 화면, 경매 운영 데스크톱, 방송 오버레이를 같은 카드/폰트 크기로 강제하지 않는다.
- 흰색·회색 바탕, 파란 주요 행동, 옹동2 로고를 유지한다. 설명은 행동·상태 이해에 필요한 것만 남긴다.
- 최초 수령·결제 등록 중에는 단계에 집중한다. 이후 내 개체와 배송·결제로 나눈다. 알림 링크는 필요한 업무를 먼저 연다.
- 업체 출품·부모 자료는 경매 실시간 item과 분리해 작성하고 운영자가 반영한다. 기존 낙찰을 출품 수정으로 덮어쓰지 않는다.
- 구매자 계정은 카카오 연동을 기본 방향으로 삼는다. 사용자가 빠른 진입을 요청했으며 모바일 카카오톡 간편로그인과 카카오싱크 첫 가입 흐름을 준비한다. 실제 앱/동의 설정은 로컬 서버 인증 구현과 구분한다.
- 실제 고객 자료를 복제한 백테스트나 테스트 알림은 실행하지 않는다. 임시 저장소·가상 자료로 검증한다.

## 코드에서 확인한 장기 이용 문제

- `platform-api.js`의 구매자 토큰 TTL은 14일이다. `buyerBundleContext`는 기본적으로 active 경매만 허용하고, 구매자 거래 GET만 archived 조회를 명시적으로 허용한다. 현재 링크 자체를 영구 보관함이라고 부를 수 없다.
- 기존 구매자 링크는 경매 ID와 전화번호 해시 범위다. 하나의 링크에 과거 모든 경매 조회 권한을 자동 추가하지 않는다.
- 번호가 같은 과거 낙찰을 자동 병합하지 않는다. 장기 보관함 소유권 확인과 과거 기록 연결 근거가 필요하다. 기존 행은 그대로 두고 승인 가능한 연결 정보만 별도로 둔다.
- 보관 경매 조회 허용 시 저장/신고/결제 변경까지 다시 열리지 않도록 읽기와 쓰기 권한을 나눈다.
- 이전 배송 지점 제안은 과거 낙찰 사진·거래금액 전체 공개와 다른 기능으로 취급한다.

## 보관 정책 초안 — 아직 자동 삭제에 적용하지 않음

- 거래 식별·금액·처리 기록과 구매자에게 보이는 개체 카드를 분리한다. 표시 기한 만료가 정산 기록 삭제가 되지 않게 한다.
- 개체 확인 사진은 우선 12개월을 검토 기준으로 잡되 사용자 확정과 저장 사용량 확인 전 자동 삭제하지 않는다. 장기 표시할 때 사진은 요청 시 읽고, 썸네일과 큰 보기를 별도로 저장한다.
- 공유 부모 사진은 참조 중인 개체가 있으면 일괄 삭제하지 않는다. 업체의 부모 정보 수정은 최신 자료로 보여주되 변경 이력은 보존한다.
- 배송 연락처는 개체 보관함에 불필요하게 반복 노출하지 않는다. 법정 기록 보관 기간·삭제 고지 등은 운영 정책 확정 시 별도로 검토한다.
- 주당 80개체에서 큰 사진 200KB+썸네일 30KB, 개체당 3장이면 약 2.87GB/년이다. 이는 부모 공유·캐시를 적용하기 전 단순 추정이며 Free 파일 저장 1GB로 무기한 보관할 수 있다는 뜻이 아니다.

2026-09-12 공식 확인: [Supabase 요금](https://supabase.com/pricing), [이미지·캐시 최적화](https://supabase.com/docs/guides/storage/production/scaling). Free 파일 저장 1GB와 일반/캐시 전송 각각 5GB. 계정의 실제 사용량은 아직 확인하지 않았다.

## 검증 원칙

위험도: 전체 공개 데이터·영속 저장·권한 연동은 release. 화면 단독 변경은 medium 또는 low로 별도 검증한다. 전체 목표를 좁은 테스트 통과로 완료 처리하지 않는다. 각 작업의 실제 명령·결과·남은 범위를 누적 기록한다.

2026-09-12 이어서 작업: 직전 턴은 업체 로컬 하단 메뉴·최초 등록 창 구현과 브라우저 검증을 완료해 progress로 분류했다. 현재 작업 트리를 다시 읽고 위 미완료 범위를 확인했다.

## 구매자 하단 메뉴 — 로컬 검증

- 첫 등록은 수령지 선택 → 결제방법 저장 순서를 유지한다. 저장 이후 `내 개체 / 배송·결제` 메뉴를 표시한다. 추가 낙찰 정보가 미저장이거나 정보를 수정 중이면 등록 화면에 집중한다.
- 내 개체는 현재 경매의 A/B 식별번호·업체·개체·금액을 표시한다. 사진이 없으면 빈 이미지 틀이나 사진 없음 문구를 만들지 않는다.
- 공통 사진 뷰어는 개체·부·모 그룹, 원본 비율, 열 때 큰 이미지 요청, 오류 안내, Escape·바깥 클릭·포커스 복귀를 지원한다. 실제 구매자 API의 사진 필드는 아직 연결하지 않았다. 사진 검증은 가상 이미지로 수행했다.
- `node --test test/checkout-item-view.test.js test/buyer-checkout-flow.test.js test/checkout-client.test.js test/checkout-guide.test.js`: 25개 통과.
- `node scratch/checkout-redesign/buyer-navigation-check.cjs`: 독립 로컬 서버·가상 자료로 통과. 탭 이동 시 저장 요청 없음, 최초 등록·추가 낙찰·미저장 변경, 사진 지연 로드·실패·키보드 닫기, 320/390/520px 및 200% 확대 확인.
- `node --check public/buyer-navigation.js`, `git diff --check -- public/buyer-shipping.html`: 통과. LF/CRLF 작업 트리 경고만 있음.
- 운영 배포 없음. 과거 경매 통합·장기 권한·실제 사진 저장·전체 역할 화면 연결은 위 목표에 계속 남아 있다.

## 실제 결제 사진 연결 — 2026-09-12

직전 목표 턴은 구매자 화면 실화면 확인과 진행 문서 갱신을 완료했으므로 progress로 분류했다. 이번에는 실제 API의 사진 누락을 확인해 수정했다. 위험도는 공개 응답 계약 변경에 해당하는 release다. 운영 배포는 하지 않았다.

- `checkout-item-data.js`가 권한 확인을 마친 개체에서 화면용 필드만 선택한다. 구매자 전체 목록·업체별 결제 묶음·판매업체 구매자 목록 모두 이 함수를 사용한다. 원본 attributes, 입찰 로그, 내부 연락처는 펼쳐 넣지 않는다.
- 기존 `photoUrl`, 부·모의 `attributes.photo_sire/photo_dam`, 향후 출품 `attributes.media/parents`를 읽는다. 경매 순서인 숫자 lotNumber와 표시용 A/B 식별번호를 구분한다. 아직 공통 부모 저장소 조회를 연결한 것은 아니므로 업체의 부모 수정 전파 전체가 완료됐다고 주장하지 않는다.
- 구매자와 업체가 같은 사진 뷰어를 사용한다. 부모 사진만 있으면 개체 썸네일을 만들지 않는다. 사진은 큰 보기 요청 시 읽고, 실패 시 재시도한다. 사진 종류 선택 시 키보드 포커스를 유지한다. 사진 보기 중에는 결제 화면의 자동 재렌더를 미룬다.
