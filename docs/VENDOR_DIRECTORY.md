# 공통 업체와 경매 참가 기록

## 운영 흐름

1. 기존 업체는 등록목록 → 업체 전용 링크 관리 → 공통 업체로 등록.
2. 다음 채널은 공통 업체 불러오기 → 해당 업체를 이 채널에 추가.
3. 이름이 같아도 자동 병합하지 않는다. 공통 업체 ID로만 연결한다.
4. 기존 `/v` 주소는 유지한다. 다른 채널에서 발급해도 최초 업체 주소를 반환한다.
5. 전용 페이지에서 경매를 선택한다. 운영 중인 경매를 기본으로 표시한다.
6. 업체 계좌 첫 등록은 링크 인증으로 가능하다. 이후 변경은 운영자만 가능하다.

## 저장 경계

- `vendor_directory_v1`: 공통 프로필, 명시적 채널 참가 연결, 고정 링크의 원래 채널/업체 식별자.
- 공통: 이름, 로고, 연락처, 계좌, 결제방식, 담당자, 주소.
- 채널별: 업체 코드, 팀, 기여도 배율, 출품·낙찰·배송·결제 데이터.
- 업체명이나 전화번호로 자동 병합하지 않는다.
- 저장된 거래의 계좌 스냅샷과 배송비를 공통 정보 변경으로 재계산하지 않는다.
- 종료된 채널의 업체 거래는 조회 가능하지만 결제 확인·카드링크 등록은 금지한다.

## 안전장치

- 공통 업체 등록/연결은 관리자 인증 필요.
- 전용 링크가 가진 공통 업체의 참가 채널만 서버에서 허용.
- 공통 프로필 버전 검사로 오래된 화면의 덮어쓰기 거부.
- 공통 디렉터리 쓰기는 프로세스 내부 직렬화. 현재 단일 Render 인스턴스 전제이며 다중 인스턴스로 확장할 경우 DB 트랜잭션/CAS로 전환해야 한다.
- 연결 재시도는 결정적 참가 ID로 중복 생성 방지.
- 공통 업체의 채널 기록 삭제는 차단. 링크는 권한을 가진 주소이므로 해당 업체에만 전달.

## 아직 자동화하지 않는 부분

- 서로 다른 기존 업체 기록을 이름만 보고 합치는 작업.
- 이미 내보낸 과거 회차 아카이브를 공통 포털에 일괄 이관하는 작업. 현재 포털의 경매 구분 단위는 채널이며, 같은 채널의 회차 아카이브는 기존 보관 기능을 사용한다.
- 전용 링크 유출 시 재발급/폐기 UI. 현재 링크의 기존 만료 정책을 유지한다.

운영 데이터를 자동 병합하거나 초기화하지 않고 단계적으로 연결한다.
