# 도도시 승차권용 배송 라벨 (2026-11-23)

## 구성

- 기존 B1 PRO 30×50mm 용지를 유지한다. 도도시 개체 한 건은 출발/도착 세로 라벨 두 장을 연속 출력한다. 파르게·직수령은 기존 한 장 형식이다.
- 사용자는 출력된 라벨을 세로로 돌려 승차권 왼쪽(출발)과 오른쪽(도착)에 붙인다. 개체번호는 오른쪽 맨 위에 한 줄로 표시한다. 승차권 자체의 번호를 만들어 넣지 않는다.
- 승차권에 항목명이 이미 있으므로 스티커에는 도도시/출발/도착/보내는 분 등의 제목을 인쇄하지 않는다. 왼쪽은 출발 정거샵·보내는 분·연락처·맡기는 날짜(요일), 오른쪽은 도착 정거샵·받는 분·연락처·찾는 날짜 순서다. 양쪽 정거샵(7~32%), 이름(39~49%), 연락처(59~70%), 날짜(79~90%)를 같은 높이의 빈칸에 맞춘다.
- 전크자 회차의 라벨 발송 기본값은 사용자 지정 `전크자`, `01049278600`. 인쇄 페이지 입력란에서 편집하며 해당 기기의 회차별 localStorage에만 저장한다. 도도시 예약서 발송인이나 배송 데이터는 변경하지 않는다.
- 기본 연락처는 인증된 관리자 API로만 전달하며 공개 JS/HTML에 넣지 않는다.
- 합배송 개체번호는 오른쪽 상단 0.5~6.5%에 번호순으로 한 줄로 표시하며 현재 개체 ID의 번호만 검은 배경/흰 글자로 표시한다. 최대 12개까지 글자 크기를 맞추고 12개 초과는 출력 전 안내한다. 방송일은 맨 아래 94~98%에 작게 표시한다.
- 흑백, 기존 Pretendard 계열을 유지한다. 방송일과 찾는 날짜는 별도 데이터다. 예상일이라는 설명은 화면에만 표시한다.
- 웹은 3:5 세로 두 장을 함께 미리보기한다. 320px에서도 가로 넘침 없이 표시한다. 실제 프린터는 기존 576×360 feed 비트맵으로 회전해 보내므로 용지 설정 변경이 필요 없다.

## 데이터/실패 처리

- 관리자 전용 `dodosi-dispatch` 조회의 최신 정거샵·발송인·수령인·예상 일정을 재사용한다. 출력 직전 다시 조회한다. 현재 조회는 신규 미발송 그룹만 반환한다. 과거/발송 완료 건 재출력은 임의로 다음 배송일을 넣지 않고 확인 필요로 막힌다.
- 최신 일정, 연락처, 정거샵 등이 없으면 이유를 표시하고 출력하지 않는다. 설정 링크는 해당 채널의 도도시 접수 페이지로 연결한다.
- `kind: dodosi_ticket` 한 건을 브리지에서 출발/도착 두 작업으로 확장한다. 모두 검증한 뒤 한 번에 enqueue하며, HTTP 요청끼리 enqueue가 섞이지 않도록 잠근다. 일부 잘못된 배치는 전체 거부한다.
- 새 capability `dodosiTicketVersion: 2` 없이는 새 도도시 출력을 거부한다. 기존 가로형은 기존 capability를 유지한다. 웹의 중복 클릭은 전송 전부터 차단한다. 의도적인 재출력은 새 호출로 허용하며 네트워크 실패를 자동 재시도하지 않는다. v1 대기열은 하단 정보가 없으므로 새 화면에서 다시 생성해야 한다.
- 배송/결제/예약/알림 데이터 변경은 없다. 실제 출력/물리 부착 치수 확인은 별도로 필요하다.

## 설치된 앱 패치

이 PC는 `CDCUP` 체크아웃보다 최신인 standalone 앱을 사용한다. 기존 앱 파일을 낡은 체크아웃으로 덮지 않는다.

`python tools/desktop-labels/install.py <standalone-app-directory>`는 검증된 v2 코드에만 최소 패치를 적용하며 원본 `.before-dodosi-20261123` 백업을 남긴다. 알 수 없는 소스는 쓰기 전 거부한다. 앱 재실행 후 적용된다. 앱 업데이트 시 이 패치가 포함되었는지 capability로 확인한다.

v2가 이미 설치된 앱의 배치 수정은 `dodosi_label_design.py`만 백업 후 갱신한다. 인쇄마다 별도 worker가 모듈을 불러오므로 다음 인쇄부터 적용되며 앱 재실행이나 대기열 변경이 필요 없다. 기존 작업에 저장된 받는 분·합배송 목록을 그대로 사용한다.

검증: `node --test test/dodosi-labels.test.js`, `CREO_LABEL_APP` 환경변수로 설치 앱 경로 지정 후 `python -m unittest discover -s tools/desktop-labels -p "test*.py"`, `node tools/verify-dodosi-labels.cjs`.
브라우저 검증은 합성 데이터 및 가짜 loopback 응답만 사용하며 실제 출력하지 않는다.

2026-11-23 검증: `npm run check` 통과, 전체 Node 2,099개 통과. 설치 앱 runtime으로 CDCUP 회귀 137개 및 새 브리지/렌더링 4개 통과. 시스템 Python의 구버전 niimprint에는 BleTransport가 없어 동일 회귀 중 1개가 실패했으므로 실제 배포 runtime으로 재검증했다. 1280/390/320px 미리보기, 두 장 계수, 중복 클릭, 구버전 capability, 보내는 분 누락 차단을 확인했다. 실물 프린터 출력은 하지 않았다.

같은 날 v2 빈칸 부착형: 전체 Node 2,100개, 설치 runtime 회귀 137개, 라벨 4개 통과. 3개 칸/현재 칸 강조, 발송 이름·연락처 편집, 새로고침 보존 및 회차 분리, v1 앱 차단을 추가 검증했다. 실제 출력 대신 프린터 렌더러의 회전 전 이미지를 검수했다.

같은 날 네 줄 정렬 수정: 전체 Node 2,101개, desktop 회귀 140개, 설치 앱 브리지와 후보 렌더러 7개 통과. 양쪽 이름 누락 회귀와 12개 번호 한 줄 경계를 검사했다. 560px/320px 실제 브라우저 미리보기에서 넘침이 없고, 실제 인쇄 렌더러의 A03 읽기 전용 미리보기도 확인했다. 별도 인쇄 명령은 보내지 않았다.
