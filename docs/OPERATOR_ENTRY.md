# 운영 화면 진입

2026-09-12. 위험도 release: 공개 경로, 브라우저 인증, 기존 고객 링크에 영향을 주는 배포다.

- `/`는 옹동2 안내 화면이다. 운영 메뉴나 로그인 링크를 표시하지 않는다.
- `/main`은 로그인 전에는 비밀번호 입력 화면만 반환한다. 서버가 서명 쿠키를 확인한 뒤 기존 운영 HTML을 반환한다.
- `/index.html`, `/main/` 및 인코딩·대소문자 별칭은 `/main`으로 정규화한다. 경매 쿼리는 유지한다.
- `CREO_OPERATOR_PASSWORD_HASH`는 별도 scrypt 해시다. 평문 비밀번호는 저장소나 브라우저 저장소에 넣지 않는다.
- 브라우저 비밀번호 변경은 기존 브라우저 세션만 무효화한다. `CREO_ADMIN_SECRET`, 구매자·업체·주관사 링크의 서명 키, PC 앱의 기존 API 인증은 유지한다.
- 운영 메인 HTML을 보호하는 변경이다. 모든 운영 도구의 HTML 셸을 새로 차단하거나 기존 PC/API 키를 폐기하는 변경은 아니다. 민감 API는 기존 권한 검사를 유지한다.
- 로그아웃 실패는 재시도할 수 있고, 성공 이후 뒤로 가기·BFCache 복원에서도 운영 화면을 다시 확인한다.
- 선택형 gateway는 보호 경로를 core에 전달한다. 별도 gateway 서버는 이번에 개설하지 않는다.

## 배포 전 검증

- `npm run check`: 통과.
- `npm test`: 649개 통과, 실패 0개. 관련 인증·경로·회귀 포함. 작업 폴더의 별도 Dodosi 테스트도 포함한 수치다.
- 실제 배포 대상만 별도 디렉터리로 내보내 운영과 같은 Node 22.23.2에서 `node --test`: 635개 통과. 제외한 별도 Dodosi 작업의 테스트 14개 차이다.
- PC `python -m unittest discover -p "test*.py"`: 189개 통과.
- 실제 로컬 Chrome: 익명 메인, 320/390/800px, 올바른/잘못된 비밀번호, 기존 별칭, 경매 선택 유지, 로그아웃 응답 실패/재시도, 뒤로 가기 3그룹 통과.
- 인증 API: 병렬 오입력 제한, 동일 설정 재시작, 비밀번호 교체 후 쿠키 거부, 기존 고객 3종 링크 유지, 헤더 키로 메인 HTML 우회 거부.

Render에는 새 해시를 `Save only`로 먼저 저장했다. 코드 배포 전에는 새 비밀번호가 적용되지 않는다. 실제 배포 커밋·운영 확인 결과는 별도 배포 기록에 남긴다. 테스트용 로컬 페이지와 개인 환경 파일은 배포에서 제외한다.
