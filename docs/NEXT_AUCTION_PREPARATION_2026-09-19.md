# 더드랍 경매 준비

## 운영 기준

- 기존 크레용 경매는 회차 기록을 추가하고 출품 접수·방송을 종료한다. 채널은 결제·배송 처리가 가능한 active 상태로 유지한다. archived는 구매자 링크를 조회 전용으로 바꾸므로 사용하지 않는다.
- 새 채널 `thedrop` / 더드랍은 크레용의 배치·색·픽셀 테마를 기반으로 준비한다. 업체, 개체, 입찰, 낙찰, 배송, 계좌, 안내 발송 기록은 복사하지 않는다.
- 이전 진행자·직수령지·배너 선택·자막·대회 규칙·경매일·출발지는 가져오지 않는다. 진행자와 배너는 등록 후 켜고, 업체·개체는 언제든 추가한다.
- P3는 업체별/낙찰자별 낙찰금액을 10초 간격으로 교대 표시한다. 출품 접수는 열고 방송은 대기한다.
- 경매일과 출발지가 정해지기 전 배송 예정일 자동 계산은 끈다. 배송사와 기본 추가 배송비는 기존 크레용 설정을 유지한다. 실제 행사 배송 조건은 시작 전에 확인한다.
- 업체 등록 → 업체 전용 링크 전달 → 출품 검토/편성 → 진행자·배너·배송 설정 확인 → 경매 시작 순서다. 아직 참여 업체와 날짜가 정해지지 않은 것은 오류가 아니라 입력 대기다.

## 구현 및 안전 경계

`tools/prepare-next-auction.cjs`는 API를 주입받는 운영 준비 도구다. 기본은 읽기만 하며 명시적인 apply 옵션에서만 기록한다. 처음 쓰기 전에 백업 콜백을 실행한다. 구 채널에서 진행 중 개체가 발견되면 중단하고 다른 운영 채널을 임의로 전환하지 않는다. 새 대상에 업체·개체·배송·자산 또는 진행 상태가 있으면 덮어쓰지 않는다.

표현 설정은 허용된 키만 복사한다. 이전 회차 기록은 동일 제목이 있으면 다시 생성하지 않는다. 버전 조건부 저장을 사용하며 중간 실패나 응답 유실 후 빈 채널에 한해 재시도할 수 있다. 이 도구가 모든 HTTP 요청을 단일 분산 트랜잭션으로 묶는 것은 아니다. 중단 시 기존 거래 기록을 보존하고 재실행 전 상태를 검사하는 방식이다. 실시간 운영 중인 채널에는 실행하지 않는다.

출발지를 명시적으로 비웠는데 크레용 대구로 복원되던 문제를 서버와 설정 폼 양쪽에서 수정했다. 필드가 아예 없는 기존 설정은 기존 기본값을 유지한다. 미설정 출발지는 예상 날짜를 만들지 않는다.

## 검증 근거

위험도 release: 운영 채널 전환·출품 접수·영속 기록·서버 배포를 포함한다.

- 최종 격리 배포 작업트리 `node --test`: **837/837 통과**. 기존 작업트리의 다른 미승인 변경과 추적되지 않은 테스트를 포함하지 않았다.
- `npm run check`: 통과.
- 데스크톱 `python -m unittest discover -p "test*.py"`: **203/203 통과**.
- 추가 시나리오: 빈 채널 생성, 거래 보존, 회차 중복 방지, DB 재시작, 새 업체/개체 등록, 중복 낙찰 요청, 낮은 낙찰가, 다음 개체, 이전 채널 쓰기 거부, 개인정보 비공개, 동시 준비, 열 단계별 실패, 네 단계의 기록 성공 후 응답 유실, 빈 출발지 재저장.
- 신규 테스트는 격리된 임시 SQLite와 가상 기록만 사용한다. 실제 낙찰 기록을 백테스트로 재생하지 않는다. 메시지를 보내지 않는다.
- 실제 로컬 화면: 업체 0/개체 0 시작, 업체 추가·가상 저장, 팀 설정 제외와 입력 이름, P1 빈 진행자, P2 이전 개체 없음, P3 빈 순위판.
- UTF-8, 인라인 JavaScript 구문, diff 검사 통과.

테스트 통과는 검증한 시나리오의 근거다. 외부 밴드·카카오 전달·배송사 일정·사용자 기기의 모든 장애를 100% 보장하지 않는다. 배포 후 health 및 정적 파일, 실제 채널·기존 거래 보존은 별도 읽기 검증으로 확인한다.
