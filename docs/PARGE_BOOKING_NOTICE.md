# 파르게 예약 확인 알림톡 · 2026-11-01

장바구니 확인 → 주문번호 연결·예약 완료 → 낙찰자별 미리보기 → 예약확인 톡 보내기.
예약 완료는 실제 발송 처리나 결제 상태를 변경하지 않는다.

## 주문번호 연결

파르게 공개 booking 페이지의 배포 JavaScript를 확인했다. 완료 화면에는 대표 주문번호와 `맡김일 안내` 아래 주문번호·맡김 날짜가 표시된다. 수령인·전화번호·도착지와의 연결은 표시되지 않는다. 따라서 확장 프로그램 1.2.0은 화면에 표시된 번호 후보만 읽는다. 운영자가 실제 주문별 수령인·연락처·도착 거점·마릿수를 대조하여 연결한다. 번호 순서로 낙찰자를 추측하지 않는다. 로그인되지 않은 현재 브라우저에서는 실제 예약 완료 화면으로 검증하지 못했으며, 공개 마크업 기준의 격리 DOM 시험을 사용한다.

서버는 주문 입력 순서가 아닌 수령인·전화·거점·수량으로 다시 대조한다. 같은 번호의 중복·다른 접수에 연결된 번호·재낙찰·배송 정보 변경·다른 회차는 거절한다. 기존 예약번호/메모 방식의 기록은 주문별 연결을 마쳐야 알림톡을 보낼 수 있다.

## 일정

- 전국크레자랑 채널의 크레오 대구본점 출발에만 월요일 방송 → 화요일 특별 출발을 적용한다. 화요일 노선부터 도착지별 배송 요일을 계산한다.
- 수요일 방송은 출발 거점의 다음 정기 수거일과 도착지별 다음 배송일을 적용한다.
- 파르게에서 확인해 입력한 수령 예정일이 있으면 해당 날짜를 우선한다. 맡김일을 수령 예정일로 복사하지 않는다. 출발일과 수령일을 모르면 날짜를 임의 확정하지 않고 최신 일정 또는 `일정 확인 중`을 쓴다.
- 공개 운송 일정이 3일 이상 오래되거나 거점이 불분명하면 예상 날짜를 제공하지 않는다.

## 발송·운영

`buyer_parge_booking_confirmed`는 아직 승인 코드가 없는 초안이다. 알리고 `@옹동` 채널에 입력한 본문은 `config/kakao-alimtalk-templates.json`에 보관한다. 사용자 확인 후 등록 신청하고, 승인된 코드·본문을 `docs/approved-alimtalk/` 및 `approved-alimtalk.js`에 연결해야 활성화된다. 등록 신청만으로 활성화하지 않는다. SMS 대체 발송은 사용하지 않는다.

발송 요청과 알림 레코드를 같은 저장 트랜잭션으로 기록한다. 접수 기록 ID·주문번호에서 만든 이벤트 키로 동시 요청·재시작·재클릭의 중복 발송을 막는다. 기존 발송 큐가 실패만 재시도하며 결과가 불명확하면 `delivery_unknown`으로 멈춘다. 발송 직전에 낙찰·연락처·거점·개체 구성·안내 날짜를 다시 검증한다. 변경된 알림은 만료시킨다. 실제 알리고 접수 완료와 최종 휴대폰 수신 성공은 다르다.

## UI 검수 기준

기존 `docs/CHECKOUT_DESIGN.md`와 `parge-dispatch.css`의 배경·표면·문자·파란 동작 색을 유지한다. 관련 better-layout/typography/colors/writing/accessibility/ui 기준으로 제목 아래 설명, 묶음별 fieldset/legend, 연결 입력, 최종 저장 순서로 구성했다. 44px 조작 영역, 16px 입력, 700px 이하 단열, 키보드 포커스, 오류 role=alert와 읽기 진행 role=status를 적용한다. 새로운 모션이나 디자인 토큰은 만들지 않는다.

## 검증 기록

- `npm run check`, 전체 웹 테스트 1,947개 통과, `git diff --check`, 변경 텍스트 UTF-8 검증 통과. 수동 출발일 예외 보완 후 재실행에서 기존 buyer-library-entry UI 대기 시험 1개가 일시 실패했으나 해당 파일 8개 단독 통과, 최종 전체 `npm test -- --test-concurrency=4` 1,947개 통과.
- 관련 신규 회귀: 주문 역순 매칭, 수령인과 낙찰자 구분, 날짜 우선 적용, 번호·거점·수량·연락처 오류, 미승인 차단, 동시 중복·재시작, 저장 실패 원자성, 오래된 미리보기, 재낙찰 및 발송 직전 연락처 변경, 화면 번호 후보 읽기.
- 격리 SQLite 화면에서 주문 연결 저장 → 예약 완료 → 미리보기 → 승인 전 발송 비활성화 확인. 320px 화면의 문서 너비 305px, 패널 너비 273px. 실제 알리고 발송·파르게 결제는 실행하지 않음.
- 데스크톱 별도 저장소 테스트 137개 중 136개 통과, 기존 `niimprint` 미설치 오류 1개. 이번 작업에서 데스크톱 코드는 수정하지 않음.
- 기존 Downloads의 확장 도구 폴더를 백업 후 1.2.0 소스로 갱신. Chrome에 로드된 확장 도구는 새로고침 1회가 필요하며 실제 파르게 완료 화면에서의 연동은 미검증.
