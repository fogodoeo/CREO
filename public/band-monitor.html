LOGIN SESSION GUIDE

로그인 세션 갱신

상태가 LOGIN_REQUIRED일 때 아래 순서대로 진행합니다. 쿠키 값은 이 상태판이나 채팅에 입력하지 않습니다.

현재 페이지—
  1. 1
    로컬 Chrome에서 신청자 목록 확인

    대상 BAND 가입 신청 페이지가 로그인된 상태로 열려야 합니다.

  2. 2
    Network 기록 후 강력 새로고침

    F12 → Network → Disable cache 체크 → 목록 삭제 → Ctrl+Shift+R

  3. 3
    실제 document 요청 복사

    Status 200, Type document인 /applications 요청을 우클릭해 Copy as cURL (bash)를 선택합니다.

  4. 4
    쿠키 메타데이터까지 Render에 저장

    권장: BAND 쿠키를 JSON 배열로 내보내 BAND_COOKIE_JSON에 넣습니다. 각 쿠키의 domain, path, httpOnly, secure, sameSite, expires를 유지해야 합니다. BAND_COOKIE_HEADER는 임시 대체 수단입니다.

  5. 5
    재배포 후 1분 확인

    Render 저장·재배포 후 이 화면이 정상 작동으로 1분 이상 유지되는지 확인합니다.

막힐 때

Provisional headers are shown

취소됐거나 캐시된 요청입니다. Network 목록을 비우고 Disable cache를 켠 뒤 강력 새로고침하여 새로 생긴 Status 200 문서를 선택합니다.

CONNECTED 뒤 LOGIN_REQUIRED

처음 CONNECTED는 Chrome 연결입니다. 1분 안에 다시 로그인 필요가 뜨면 세션 형식을 확인합니다. HEADER라면 쿠키 domain 정보가 없는 상태이므로 BAND_COOKIE_JSON 방식으로 다시 넣습니다.

재배포할 때마다 다시 로그인

CREOK의 Persistent Disk에 /var/data/band-monitor/chrome-profile을 유지합니다. 재배포 중 신청은 BAND에 남으며 모니터 재가동 후 다시 처리됩니다.

Console의 document.cookie는 HttpOnly 세션이 빠질 수 있어 사용하지 않습니다. 쿠키를 채팅에 붙여넣지 마세요.
